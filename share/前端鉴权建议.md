# AgentGuard Vue Dashboard 鉴权方案

## 1. 边界

Dashboard 不做用户登录，不保存长期 token，不生成 launch code，不负责启动浏览器。前端只处理：

- HttpOnly browser session cookie；
- Pinia 内存中的 CSRF token 和过期时间；
- pending approval 返回的一次性 approval nonce。

`AGENTGUARD_CONTROL_TOKEN`、`AGENTGUARD_ADAPTER_TOKEN` 和 `Authorization: Bearer` 不得进入前端代码、前端 env、持久化存储或日志。

## 2. 启动与会话恢复

当前本地启动链路：

```text
Launcher 使用 control token 请求 POST /v1/auth/browser/launch
→ 输出 http://localhost:5173/?launch_code=lc_xxx
→ Dashboard 读取 launch_code
→ POST /v1/auth/browser/exchange
→ Guard API 设置 HttpOnly Cookie，返回 csrf_token 和 expires_at
→ Dashboard 从地址栏删除 launch_code
```

`launch_code` 位于 URL query，只能使用一次，默认有效期 300 秒。页面刷新时，`authStore.bootstrap()` 在无 launch code 时请求 `GET /v1/auth/browser/me`，从 browser session 恢复 CSRF token 和过期时间。

交换成功后使用 `history.replaceState` 删除 `launch_code`，保留 pathname、其他 query 和 hash。交换失败时不重试旧 code，而是显示需要重新从 launcher 打开 Dashboard。

## 3. 本地开发配置

Dashboard 通过 Vite 代理以同源方式访问 Guard API：

```env
VITE_API_BASE_URL=/api/v1
VITE_BACKEND_TARGET=http://127.0.0.1:8088
```

`VITE_API_BASE_URL` 是浏览器请求前缀；`VITE_BACKEND_TARGET` 只由 Vite 代理使用。浏览器统一使用 `localhost:5173`，不与 `127.0.0.1:5173` 混用。

## 4. Browser Session

Guard API 设置：

```http
Set-Cookie: agentguard_session=sess_xxx; HttpOnly; SameSite=Strict; Path=/; Max-Age=3600
```

session id 只由浏览器作为 HttpOnly Cookie 携带。前端不读取、复制或持久化 session id。共享 `requestJson` 封装通过 `fetch` 设置 `credentials: "include"`。

退出时请求 `POST /v1/auth/browser/logout`。Guard API 撤销服务端 session 并删除 cookie，前端清空 CSRF token 和过期时间。当前 logout 使用 browser session 鉴权，不要求 CSRF header。

## 5. CSRF 与审批

CSRF token 随 exchange 或 `/me` 响应返回，只保存在 Pinia 内存。当前 `POST /v1/approvals/{approval_id}/resolve` 必须同时提交：

```http
Cookie: agentguard_session=sess_xxx
X-AgentGuard-CSRF: csrf_xxx
Content-Type: application/json

{
  "decision": "allow_once",
  "approval_nonce": "nonce_xxx"
}
```

approval nonce 由 `GET /v1/approvals/pending` 针对当前 browser session 签发，绑定 `approval_id`、`tool_call_id` 和 session，只能消费一次。前端原样回传 nonce，不记录完整 nonce。

## 6. Dashboard 数据接口

browser session 可访问的当前接口：

```text
GET  /v1/audit/events
GET  /v1/metrics/eval
GET  /v1/approvals/pending
POST /v1/approvals/{approval_id}/resolve
```

调查详情不请求独立 Trace API，而是从已加载的 AuditEvent 中按 `trace_id` 聚合。

## 7. 失效和安全处理

- `401`：清空前端会话状态，停止后续状态改变请求。
- `403`：保留 session，按 CSRF、scope 或 approval nonce 错误展示失败信息。
- 不在 `localStorage`、`sessionStorage`、IndexedDB 或持久化 Pinia 中保存鉴权状态。
- 不记录 launch code、approval nonce、CSRF token、Cookie 或 Authorization header。
