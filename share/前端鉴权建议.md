# AgentGuard Vue Dashboard 鉴权方案

## 1. 核心原则

Vue Dashboard 不做用户登录，不做 Dashboard 解锁，不保存长期 token，不生成 launch code，不负责启动浏览器。

Vue Dashboard 只处理浏览器短期会话：

```text
HttpOnly browser session cookie
Pinia 内存中的 CSRF token
审批接口返回的 approval nonce
```

长期凭证不得进入前端：

```text
AGENTGUARD_CONTROL_TOKEN
AGENTGUARD_ADAPTER_TOKEN
任何 component token
Authorization Bearer token
```

Dashboard 启动链路由 CLI / Launcher 与 Core 完成：

```text
CLI / Launcher 使用 control token 调用 Core
Core 生成一次性 launch code
CLI / Launcher 拼接 Dashboard URL
有 GUI 时尝试打开浏览器
无 GUI 或打开失败时打印 URL
Vue 读取 URL fragment 中的 code
Vue 调用 Core 交换 browser session
Core 设置 HttpOnly Cookie 并返回 csrf_token
Vue 清除 URL 中的 code 后进入 Dashboard
```

## 2. Dashboard 启动职责

### 生产模式

生产模式由 Core 托管 Vue 静态文件：

```text
Core API:        http://127.0.0.1:8088/v1/*
Vue 静态页面:   http://127.0.0.1:8088/ui/*
```

CLI / Launcher 拼接 Dashboard URL：

```text
http://127.0.0.1:8088/ui/#/launch?code=lc_xxx
```

### 开发模式

开发模式通常前后端分离：

```text
Core API:   http://127.0.0.1:8088
Vue Vite:   http://127.0.0.1:5173
```

CLI / Launcher 拼接 Dashboard URL：

```text
http://127.0.0.1:5173/#/launch?code=lc_xxx
```

`code=lc_xxx` 始终由 Core 生成。Vue 开发服务器地址可以来自配置，launch code 不能由 Vue 生成。

推荐开发环境统一使用 `127.0.0.1`，避免 `localhost` 与 `127.0.0.1` 混用导致 Cookie、CORS、Host 校验问题。

```env
VITE_AGENTGUARD_API_BASE=http://127.0.0.1:8088
```

## 3. 无 GUI 与 WSL 行为

无图形化界面时不得强制打开浏览器。启动命令输出可访问链接。

生产模式输出：

```text
AgentGuard Dashboard is ready.

Open this URL in your browser:

http://127.0.0.1:8088/ui/#/launch?code=lc_xxx
```

开发模式输出：

```text
Core API:
http://127.0.0.1:8088

Dashboard:
http://127.0.0.1:5173/#/launch?code=lc_xxx
```

WSL2 通常支持 Windows 浏览器访问 WSL 的 `127.0.0.1`。如果 Vite 无法从 Windows 浏览器访问，开发服务器可监听 `0.0.0.0`：

```bash
pnpm run dev -- --host 0.0.0.0
```

Core 默认仍应监听：

```text
127.0.0.1:8088
```

确需开放 Core 地址时，必须保留 Bearer token、Host、Origin、CORS allowlist 和 scope 校验。

## 4. Launch Code Exchange

Vue 路由：

```text
#/launch?code=lc_xxx
```

Vue 从 URL fragment 中读取 `code` 后调用：

```http
POST /v1/auth/browser/exchange
Content-Type: application/json

{
  "launch_code": "lc_xxx"
}
```

`/v1/auth/browser/exchange` 不要求已有 browser session，但必须校验：

```text
launch code 存在
launch code 未过期
launch code 未使用
Host 合法
如果请求包含 Origin，则 Origin 必须在允许列表内
```

Core 校验成功后执行：

```text
创建 browser session
设置 HttpOnly Cookie
返回 csrf_token 和 expires_at
失效当前 launch code
```

响应：

```json
{
  "authenticated": true,
  "expires_at": "2026-06-06T17:00:00+08:00",
  "csrf_token": "csrf_xxx"
}
```

Vue 成功交换后必须通过 Vue Router 跳转到 Dashboard 首页，清除 URL 中的 launch code。不要在代码中写死 `/ui/`。

推荐：

```ts
router.replace({ name: "dashboard" });
```

或使用当前 router base 计算目标路径。

## 5. Browser Session

Core 设置 browser session cookie：

```http
Set-Cookie: agentguard_session=sess_xxx; HttpOnly; SameSite=Strict; Path=/v1; Max-Age=3600
```

规则：

```text
HttpOnly: Vue 不能读取 session id
SameSite=Strict: 降低跨站请求风险
Path=/v1: 只发送给 Core API
Max-Age=3600: 默认 1 小时有效
```

HTTP 开发环境不设置 `Secure`。后续使用 HTTPS 时增加：

```http
Secure
```

Vue 请求必须启用凭证携带：

```ts
import axios from "axios";

export const api = axios.create({
  baseURL: import.meta.env.VITE_AGENTGUARD_API_BASE
    ? `${import.meta.env.VITE_AGENTGUARD_API_BASE}/v1`
    : "/v1",
  withCredentials: true,
  timeout: 15000,
});
```

生产同源部署时不配置 `VITE_AGENTGUARD_API_BASE`。开发模式可配置：

```env
VITE_AGENTGUARD_API_BASE=http://127.0.0.1:8088
```

## 6. CSRF

CSRF token 由 Core 在创建 browser session 时生成，并随 `/v1/auth/browser/exchange` 或 `/v1/auth/browser/me` 返回给 Vue。

Vue 只在 Pinia 内存中保存 CSRF token：

```ts
state: () => ({
  isAuthenticated: false,
  expiresAt: null as string | null,
  csrfToken: null as string | null,
});
```

使用 browser session 鉴权的状态改变请求必须带：

```http
X-AgentGuard-CSRF: csrf_xxx
```

需要 CSRF 的方法：

```text
POST
PUT
PATCH
DELETE
```

CSRF 只适用于 browser session 鉴权。Adapter / CLI 使用 Bearer token 的请求不使用 CSRF。

Axios 请求拦截器：

```ts
api.interceptors.request.use((config) => {
  const authStore = useAuthStore();
  const method = (config.method || "get").toLowerCase();
  const needsCsrf = ["post", "put", "patch", "delete"].includes(method);

  if (needsCsrf && authStore.csrfToken) {
    config.headers["X-AgentGuard-CSRF"] = authStore.csrfToken;
  }

  return config;
});
```

## 7. Session 恢复与退出

页面刷新后 Pinia 内存状态丢失，Vue 启动时调用：

```http
GET /v1/auth/browser/me
```

`/v1/auth/browser/me` 规则：

```text
只接受有效 browser session cookie
不接受 Bearer token
不创建新 session
默认不延长 session
返回 authenticated、expires_at、csrf_token
```

有效响应：

```json
{
  "authenticated": true,
  "expires_at": "2026-06-06T17:00:00+08:00",
  "csrf_token": "csrf_xxx"
}
```

无效响应：

```json
{
  "authenticated": false
}
```

退出接口：

```http
POST /v1/auth/browser/logout
Cookie: agentguard_session=sess_xxx
X-AgentGuard-CSRF: csrf_xxx
```

Core 执行：

```text
撤销 server-side session
清除 cookie
```

响应 Header：

```http
Set-Cookie: agentguard_session=; HttpOnly; SameSite=Strict; Path=/v1; Max-Age=0
```

## 8. Dashboard API 权限

Dashboard 读接口：

| 接口                              | 权限              |
| --------------------------------- | ----------------- |
| `GET /v1/audit/events`            | `audit:read`      |
| `GET /v1/audit/traces/{trace_id}` | `trace:read`      |
| `GET /v1/provenance/{trace_id}`   | `provenance:read` |
| `GET /v1/metrics/*`               | `metrics:read`    |
| `GET /v1/approvals/pending`       | `approval:read`   |

审批接口：

```http
POST /v1/approvals/app_123/resolve
Cookie: agentguard_session=sess_xxx
X-AgentGuard-CSRF: csrf_xxx
Content-Type: application/json

{
  "decision": "allow_once",
  "approval_nonce": "nonce_xxx"
}
```

审批 resolve 必须同时校验：

```text
browser session 有效
session 具备 approval:resolve scope
CSRF token 正确
approval nonce 正确
approval status = pending
approval 未过期
decision 属于允许选项
```

## 9. Approval Nonce

`approval_nonce` 用于保护单次审批操作。

生成规则：

```text
Core 在返回 pending approval 时生成 approval nonce
nonce 按 browser session 生成
同一个 approval 对不同 browser session 返回不同 nonce
nonce 绑定 approval_id + session_hash + tool_call_id + decision_options
nonce 短期有效
nonce 使用一次后立即失效
```

`GET /v1/approvals/pending` 返回：

```json
[
  {
    "approval_id": "app_123",
    "tool_call_id": "call_456",
    "decision_options": ["allow_once", "deny"],
    "approval_nonce": "nonce_xxx",
    "expires_at": "2026-06-06T17:00:00+08:00"
  }
]
```

Vue 提交审批时必须原样带回 `approval_nonce`。不得在 console、网络错误日志、审计日志中记录完整 nonce。

## 10. 前端禁止事项

Vue 禁止保存长期组件凭证：

```text
AGENTGUARD_CONTROL_TOKEN
AGENTGUARD_ADAPTER_TOKEN
component token
Authorization Bearer token
```

Vue 不得尝试读取、复制、转存 `agentguard_session`。session id 只能作为 HttpOnly Cookie 由浏览器自动携带。

Vue 不得将鉴权状态持久化到：

```text
localStorage
sessionStorage
IndexedDB
持久化 Pinia 插件
前端 env
打包后的静态资源
```

Pinia 只保存运行期状态：

```text
isAuthenticated
expiresAt
csrfToken
```

不得在日志中记录完整：

```text
launch code
approval nonce
CSRF token
Cookie
Authorization header
```

## 11. 失效处理

`/v1/auth/browser/exchange` 失败：

```text
清空本地 auth state
显示需要从本机启动器重新打开 Dashboard
不重试旧 launch code
```

任意 API 返回 `401`：

```text
清空本地 auth state
停止继续提交审批或状态改变请求
提示会话已失效
```

任意 API 返回 `403`：

```text
保留 session 状态
按接口错误提示展示无权限、CSRF 失败或审批 nonce 无效
```

页面刷新：

```text
先调用 /v1/auth/browser/me
有效则恢复 csrfToken 和 expiresAt
无效则进入未认证状态
```

## 12. CORS

生产模式推荐 Core 同源托管 Vue 静态资源，不启用跨域。

开发模式才启用 CORS allowlist：

```text
Access-Control-Allow-Credentials: true
Access-Control-Allow-Origin: http://127.0.0.1:5173
Access-Control-Allow-Headers: Content-Type, X-AgentGuard-CSRF, Authorization
Access-Control-Allow-Methods: GET, POST, PUT, PATCH, DELETE, OPTIONS
```

禁止：

```text
Access-Control-Allow-Origin: *
```

当 `Access-Control-Allow-Credentials: true` 时，`Access-Control-Allow-Origin` 必须是明确 Origin。

## 13. P0 前端实施清单

```text
新增 launch 路由
从 fragment 读取 code
调用 /v1/auth/browser/exchange
成功后通过 Vue Router 清除地址栏 code
API client 启用 withCredentials
支持 VITE_AGENTGUARD_API_BASE
Pinia auth store 只保存 csrfToken、expiresAt、isAuthenticated
请求拦截器为 browser session 的状态改变请求添加 X-AgentGuard-CSRF
应用启动时调用 /v1/auth/browser/me
实现 /v1/auth/browser/logout 调用
401 时清空本地 auth state
审批 resolve 提交 approval_nonce
禁止任何长期 token 进入前端代码、env、存储和日志
```
