# AgentGuard 统一鉴权管理方案

## 1. 核心边界

AgentGuard P0 采用本地 Capability Auth，不做用户登录或 Dashboard 解锁。鉴权区分三类调用方：

| 调用方           | 凭证                     | 用途                       |
| ---------------- | ------------------------ | -------------------------- |
| CLI / Launcher   | control token            | 创建 launch code           |
| Adapter / Plugin | adapter token            | 评估事件、写审计、等待审批 |
| Vue Dashboard    | HttpOnly browser session | 读取监督数据并处理审批     |

审批 resolve 额外使用 CSRF token 和一次性 approval nonce。长期 control/adapter token 不进入浏览器。

## 2. 角色与 Scope

| 角色      | 使用方                 | Scopes                                                 |
| --------- | ---------------------- | ------------------------------------------------------ |
| `control` | CLI / Launcher         | `auth:launch`                                          |
| `adapter` | LangGraph 及评测适配器 | `event:evaluate`, `event:audit:write`, `approval:wait` |

Bearer token 验证成功后生成 `AuthContext`。Adapter 不具有 `approval:resolve`，control 不具有事件评估或 Dashboard 数据权限。Browser session 当前直接作为 Dashboard 接口的会话边界，不生成 dashboard `AuthContext`。

## 3. 当前接口鉴权

| 接口                                       | 鉴权                                    |
| ------------------------------------------ | --------------------------------------- |
| `GET /health`                              | 无                                      |
| `POST /v1/auth/browser/launch`             | control token + `auth:launch`           |
| `POST /v1/auth/browser/exchange`           | 一次性 launch code                      |
| `GET /v1/auth/browser/me`                  | browser session                         |
| `POST /v1/auth/browser/logout`             | browser session                         |
| `POST /v1/guard/evaluate`                  | adapter token + `event:evaluate`        |
| `POST /v1/audit/events`                    | adapter token + `event:audit:write`     |
| `GET /v1/approvals/{approval_id}/wait`     | adapter token + `approval:wait`         |
| `GET /v1/audit/events`                     | browser session                         |
| `GET /v1/metrics/eval`                     | browser session                         |
| `GET /v1/approvals/pending`                | browser session                         |
| `POST /v1/approvals/{approval_id}/resolve` | browser session + CSRF + approval nonce |

## 4. 长期 Token

Guard API 从环境变量读取：

```env
AGENTGUARD_CONTROL_TOKEN=ag_control_xxx
AGENTGUARD_ADAPTER_TOKEN=ag_adapter_xxx
```

Bearer 校验使用 constant-time compare 与上述配置值比较，然后生成固定的 control 或 adapter `AuthContext`。当前没有凭证数据库、token 生成 CLI、轮换或撤销流程。

开发环境有默认演示值。当 `AGENTGUARD_ENV=production` 时，如果 token 或数据库 URL 仍为默认值，Guard API 拒绝启动。

## 5. Launch Code 与 Browser Session

control token 通过 `POST /v1/auth/browser/launch` 创建 launch code。launch code 默认有效 300 秒，只能消费一次；服务端只持久化其 SHA-256 hash。

Dashboard 调用 `POST /v1/auth/browser/exchange` 后，Guard API：

- 消费 launch code；
- 创建默认有效 3600 秒的 browser session；
- 以 `HttpOnly; SameSite=Strict; Path=/` 设置 `agentguard_session` cookie；
- 返回 `csrf_token` 和 `expires_at`。

browser session 在 Control Plane store 中只保存 session hash、CSRF token、过期时间和撤销时间。默认实现使用 PostgreSQL；`MemoryControlPlaneStore` 用于测试。logout 撤销服务端 session 并删除 cookie。

## 6. CSRF 与 Approval Nonce

当前 CSRF 校验用于审批 resolve。Dashboard 在 `X-AgentGuard-CSRF` header 中提交 exchange 或 `/me` 返回的 token。

`GET /v1/approvals/pending` 为当前 session 签发 approval nonce。服务端只持久化 nonce hash，并绑定 `approval_id`、session 和 `tool_call_id`。resolve 时先校验 CSRF，再消费 nonce，最后将 approval 更新为 `allow_once` 或 `deny`。

## 7. 存储与失效

| 状态            | 存储                            | 失效条件           |
| --------------- | ------------------------------- | ------------------ |
| launch code     | PostgreSQL 中的 hash            | 消费或过期         |
| browser session | PostgreSQL 中的 hash 与会话字段 | logout、撤销或过期 |
| CSRF token      | browser session 记录            | session 失效       |
| approval nonce  | PostgreSQL 中的 hash 与绑定字段 | 消费或过期         |

长期 control/adapter token 不写入数据库。任何完整 token、launch code、session id、CSRF token、approval nonce、Cookie 或 Authorization header 都不得写入日志或审计事件。

## 8. 当前错误码

| 场景                              | 状态码 | 错误码                   |
| --------------------------------- | ------ | ------------------------ |
| 缺少 Authorization                | `401`  | `AUTH_MISSING`           |
| Bearer 格式或 token 无效          | `401`  | `TOKEN_INVALID`          |
| Scope 不足                        | `403`  | `SCOPE_DENIED`           |
| Session 无效                      | `401`  | `SESSION_INVALID`        |
| Session 过期                      | `401`  | `SESSION_EXPIRED`        |
| Launch code 无效或已消费          | `401`  | `LAUNCH_CODE_INVALID`    |
| Launch code 过期                  | `401`  | `LAUNCH_CODE_EXPIRED`    |
| CSRF 失败                         | `403`  | `CSRF_INVALID`           |
| Approval nonce 无效、过期或已消费 | `403`  | `APPROVAL_NONCE_INVALID` |

## 9. P0 不做

```text
用户登录
Dashboard 解锁
用户注册
找回密码
多租户
复杂 RBAC 页面
OAuth
SSO
JWT
mTLS
每个请求签名
动态适配器注册
远程适配器接入
token 管理 UI
每个 runtime 默认独立 token
每个 agent 默认独立 token
```

## 10. P1 扩展方向

P1 扩展不得推翻 P0 的 `AuthContext + scope` 模型。

可扩展项：

```text
每个 runtime + agent_id 独立 adapter token
token rotate / revoke CLI
更细粒度 adapter scopes
Dashboard token 管理页面
多 browser session 管理
审批通道 token
远程访问时启用 HTTPS 和更强认证
```
