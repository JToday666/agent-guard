## D1：assessment_digest shadow 期计算口径（时点矛盾消解）

### 决策

`assessment_digest` 在 V21-08 shadow 期即实现计算，口径为：

1. 输入 = `FastAssessment.digest_fields()` / `DecisionEvidenceV21.digest_fields()`
   **已冻结白名单**投影（`packages/agentguard-core/agentguard_core/decisions/evidence.py`
   L183-214、L264-297），白名单本身**一字不改**；
2. 规范化 = RFC 8785 JCS / 项目统一 canonical JSON（01 §29，L1164-1184），经
   `canonical_sha256` 计算；01 §29 禁入字段（wall-clock latency、random UUID、
   display-only reason、provider request id、debug metadata）一律不入摘要；
3. V21-09 正式 `assess/finalize`（完整方案 §15，L3181-3198）**复用同一计算函数**，
   不另立口径。

同步修订 `evidence.py` scaffold docstring 的时点声明（FastAssessment 类 docstring
L146-148 与 `digest_fields()` docstring L185-191 中"digest 计算留待 V21-09"改为
"V21-08 shadow 期实现计算"口径）——**只改注释，不改任何冻结字段与白名单**。

**注**：本决策记录只冻结口径；上述 docstring 修订在 V21-08 后续代码任务（shadow
assess 实现提交）中执行，不在本文档提交内。

### 背景

存在时点矛盾：scaffold docstring 声明"canonical digest 计算留待 V21-09"
（`evidence.py` L146-148），而完整方案 §14（L3157-3161）明确要求"**DecisionEvidenceV21
不等到后期才做**"、"Shadow 即保存：assessment_digest；……"。白名单已在 V21-01 冻结且
逐字对齐 01 §29（L1162-1181 口径），矛盾仅在"计算实现的阶段归属"，属 IMPLEMENTATION
级时点问题，不触及任何冻结字段。

### 否决的替代

**shadow 期不实现 assessment_digest（等 V21-09）**：直接违反完整方案 §14"shadow 即
保存 assessment_digest"的逐字要求，且使 shadow 期审计证据缺少可复算锚点、divergence

### 状态

## D2：divergence_category 受控词表（九宫格 + 降级类目）

### 决策

`DecisionEvidenceV21.divergence_category`（01 §28，L1146，类型 `str | None`）采用
受控词表，由 `legacy decision ∈ {allow, ask, deny}` × `v21 FastDisposition ∈
{CLEAR_ALLOW, DEFER, CLEAR_DENY}` 九宫格定义；**parity 对角线为 `None`**：

| legacy \ v21 | CLEAR_ALLOW | DEFER | CLEAR_DENY |
|---|---|---|---|
| **allow** | `None`（parity） | `legacy_allow__v21_defer` | `legacy_allow__v21_clear_deny` |
| **ask** | `legacy_ask__v21_clear_allow` | `None`（parity） | `legacy_ask__v21_clear_deny` |
| **deny** | `legacy_deny__v21_clear_allow` | `legacy_deny__v21_defer` | `None`（parity） |

对角线依据：finalize 最小映射 CLEAR_ALLOW→allow、DEFER→ask、CLEAR_DENY→deny 与
legacy 决策一致即无分叉，记 `None`。

九宫格外另设两个**降级类目**（shadow 因降级无法产出可信 disposition 时取代九宫格值，
不得静默归入任何九宫格）：

- `degraded_no_snapshot`：事件无 task 引用 / 无 Snapshot 可读（禁伪造 Snapshot，
  01 §25，L964 起）；
- `degraded_component_failure`：shadow 组件（ActionIR / fusion 求值 / snapshot 读取
  等）异常，收敛为 `EvaluationDegradation`。

上表完整覆盖完整方案 §14（L3173-3177）列出的三个分析组合：
`legacy allow / v21 deny` → `legacy_allow__v21_clear_deny`；
`legacy ask / v21 allow` → `legacy_ask__v21_clear_allow`；
`legacy deny / v21 defer` → `legacy_deny__v21_defer`。
词表封闭：实现侧映射函数须对全部 3×3 + 2 降级类目穷尽，出现未定义组合即
fail-closed（不得自造新词）。

### 背景

完整方案 §14 只给出三个示例组合，未冻结完整词表；离线 divergence 分析（V21-10
pre-enable gate"shadow divergence 已解释"的数据源）需要机器可聚合的封闭字符串词表，
否则九宫格统计口径会在实现中漂移。

### 状态

**已冻结**（IMPLEMENTATION 级；`divergence_category` 字段类型 `str | None` 为既有
冻结字段，词表属其取值口径的实施级收敛，不修改 01 §28 正文）。

## D3：shadow feature flag 命名与默认值

### 决策

1. 环境变量 `AGENTGUARD_V21_SHADOW_ENABLED`，guard-api settings 字段
   `v21_shadow_enabled`，**默认 `false`**；
2. 实现范式仿 `apps/guard-api/guard_api/settings.py` 既有 `llm_approval_enabled`
   （L80-84，`AGENTGUARD_LLM_APPROVAL_ENABLED` 经 `_env_bool` 默认 False）；
3. flag off 时 shadow 全链路不执行，`evaluate()` 行为与审计 evidence 形状逐字节不变；
   flag on 且 shadow 任何异常一律收敛为 degradation，不改变 legacy decision。

### 背景

shadow 阶段的底线是"legacy = 唯一官方决策者、V2 不改变执行"；默认开启会直接把未验收
的融合判定挂进生产审计面，违反 04 §22 shadow-only 分离审阅的精神与零回归底线。

### 否决的替代

**flag 默认开启**：违反 legacy official 原则与零回归底线；否决。

### 状态

**已冻结**（IMPLEMENTATION 级；不新增冻结契约，属 guard-api 配置面实施约定）。

## D4：evidence refs 条数上限与 state_delta_v21 信封归属

### 决策

1. `DecisionEvidenceV21` 引用型字段**只存 id / digest 引用**，不内嵌完整对象：
   `signal_ids`、`policy_violation_ids`、`degradation_ids` **每类上限 32 条**，
   `flow_path_refs` **上限 16 条**；
2. 超出上限时**截断并记入 degradation**（计入 `degradation_ids` 并在
   `reason_codes` 留痕），禁止静默丢弃、禁止 fail-open；
3. `state_delta_v21` 信封（`contract_freeze.yaml` L85
   `state_delta_evidence_location`）**归属 V21-09**（随投影记录存储）；
   V21-08 只落 `evidence.decision_v21`（`contract_freeze.yaml` L84
   `v21_evidence_location`），不新增第二条审计记录。

### 背景

`decision_v21` 信封与 legacy evidence 同存于**同一条** policy_evaluation 审计记录，
受既有 evidence 体积预算约束（guard-api `enforce_evidence_budget`，64 KiB）；Postgres
审计写入持全局 advisory lock 串行化，evidence 膨胀直接抬高锁持有时间。上限取值理由：
单次评估的 detector signal / violation / degradation 典型规模远低于 32，flow 路径典型
深度远低于 16；该余量既覆盖正常流量，又为恶意 state flood 场景（02 §5 防 flood
语义）给出有界、可审计的截断行为。截断本身作为 degradation 记录，保证"证据不完整"
这一事实可被 divergence 分析观测（与 D2 `degraded_component_failure` 同类语义）。

### 状态

**已冻结**（IMPLEMENTATION 级；上限数值属实施级预算，字段形状不动；
`state_delta_v21` 在 V21-09 实施前不落盘）。

## D6：交付模式裁决（单 worktree / 单 PR / 多原子提交）

### 决策

1. V21-08 整任务以**单一 worktree、单一分支**（`feat/v21-08-fusion-shadow`，自 dev
   切出）开发，最终**合并为单个 PR**，PR 内按依赖序组织多个原子逻辑提交（单一目的、
   代码与测试同提交、可单独回滚），提交信息中文 Conventional Commits；
2. `04_兼容迁移与实施计划.md` §22"PR 拆分纪律"（L541-559：structure-only /
   shadow-only / behavior change / benchmark data 分开审阅）经所有者裁决**放宽为
   提交级分离**：提交顺序仍严格遵循 structure-only（T1）→ shadow-only（T2-T6）→
   benchmark/工具（T7-T8）的纪律，便于按提交审阅；
3. PR 描述含背景 / 改动 / 测试验证 / 影响范围四节，并按提交列出审阅顺序。

### 背景

04 §22 的分离目的是防止"重构模型 + 改 detector + 改阈值 + 改 benchmark"混在一个
审阅单元；提交级分离保留该目的的实质（每类变更独立可审阅、可独立 revert），代价是
单次 PR 体量显著超过 400 行常规目标，以按提交审阅顺序缓解。整任务保持单分支也避免
多 worktree 并行编码的分支错乱风险。

### 状态

**已冻结**（IMPLEMENTATION 级流程裁决；04 §22 正文逐字不动，放宽仅对 V21-08 本次
交付生效，不构成对后续阶段的先例豁免）。

## D7：PROJECTOR_VERSION 不 bump 与回滚预案要点

### 决策

1. V21-08 期间 `PROJECTOR_VERSION` **恒保持 `v21-07.projector.2`**，不发生任何
   bump（呼应 `10_决策记录_V21-05-06-07前置.md` D2"唯一一次 bump"已在 Phase 2
   消耗、D5 回滚约束）；
2. V21-08 不向 `SecurityStateDeltaV21` typed 容器新增写入语义、不改变投影 digest
   链，shadow 证据只经审计 `evidence.decision_v21` 旁路留存；
3. 回滚预案要点：
   - `decision_v21` 为 **append-only 审计键**：flag 关闭后新记录不再携带该键，历史
     记录保留不删，无数据残留负担，replay 兼容（历史无该键的记录照常重放）；
   - **flag 关闭即回退**：`AGENTGUARD_V21_SHADOW_ENABLED=false`（默认值）使全部
     shadow 代码路径不执行，`evaluate()` 回到逐字节现状；
   - 因不发生版本 bump，**不触发 D5 的 projection_records 处置约束**；若上线后需
     代码级回滚，回滚预案仍须按 D5 口径核对 `projection_records` 版本行（本阶段
     预期无新版本行，核对即通过）。

### 背景

shadow 的契约定位是"旁路只读 + 审计侧信道"：不改投影、不改 digest、不改决策。任何
PROJECTOR_VERSION bump 都会引入 reprojection 与 D5"新→旧无 decoder"的 fail-closed
回滚负担，与 shadow 可瞬时关闭的运维目标冲突。

### 状态

**已冻结**（IMPLEMENTATION 级；作为 V21-08 上线回滚预案的前置留痕，对应 04 §21
最小门禁第 12 项 rollback path documented，L524-537）。
