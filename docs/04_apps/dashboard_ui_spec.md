# AgentGuard Dashboard 前端与 UI 设计规范

## 1. 文档定位

本规范适用于 `apps/dashboard/**` 中的页面、共享组件、样式、图表和用户可见文案，是 Dashboard 后续 UI 修改的目标约束。

相关文档的职责边界：

- [Dashboard 与审批流](dashboard_design.md) 定义页面职责、数据来源、鉴权边界和交付范围。
- [接口契约与事件模型](../02_core/interface_contract.md) 定义接口、字段和状态含义。
- [AgentGuard Vue Dashboard 鉴权方案](../07_auth/前端鉴权建议.md) 定义 browser session、CSRF token 和启动链路。
- 本规范定义信息架构、视觉层级、交互模式、内容表达和前端实现要求。

本规范中的“必须”“不得”是强制要求，“应”“优先”是默认选择。若现有实现与本规范不一致，后续相关修改应向本规范收敛，但不得借机改动任务范围外的代码。

AgentGuard Dashboard 是运行时安全监督工作台，核心工作流是：

```text
发现需要关注的事件
→ 调查事件和任务链路
→ 核对规则、原因与证据
→ 处理人工审批
→ 确认防护结果与系统状态
```

页面价值来自事实清晰、调查高效、操作审慎和状态可信，不来自装饰性数据展示。

## 2. 产品任务与设计原则

### 2.1 用户需要回答的问题

Dashboard 必须帮助用户快速回答：

1. Guard API、数据库、防护链路和审计数据是否正常。
2. 当前审计窗口发生了什么，哪些事件需要优先处理。
3. Agent 尝试执行了什么动作，目标资源是什么。
4. Guard 做出了什么决策，为什么做出该决策。
5. 一条事件属于哪条证据链，已知事实是否完整。
6. 待审批动作放行后会产生什么影响。
7. 防护效果和系统诊断数据来自哪里、覆盖什么时间范围。

### 2.2 设计原则

- **工作台优先**：除安全总览外，页面默认以表格、列表、时间线、定义列表和分栏工作区承载内容。
- **事实优先**：只展示 Guard API 提供或由已加载数据确定性派生的事实。
- **证据优先**：安全结论必须能够下钻到原因、规则、事件、Trace 或节点证据。
- **操作审慎**：高影响操作必须靠近其上下文、影响和作用范围。
- **局部降级**：单个接口或区块失败不得清空其他已成功加载的内容。
- **密度适中**：相同信息保持可比较，不用过大字号、过宽留白或重复容器降低扫描效率。
- **一致可预期**：相同状态、字段、操作和反馈在不同页面使用相同文案与交互。

### 2.3 信息顺序

详情和操作页面优先使用以下顺序：

```text
上下文 Context
→ 摘要 Summary
→ 证据 Evidence
→ 操作 Action
```

不得先展示操作按钮，再让用户寻找工具、目标、原因或影响。

## 3. 信息架构与导航

### 3.1 主导航

主导航顺序固定为：

| 顺序 | 页面     | 路由                       | 核心对象                     |
| ---- | -------- | -------------------------- | ---------------------------- |
| 1    | 安全总览 | `/overview`                | 当前安全态势与待分诊信息     |
| 2    | 事件调查 | `/investigations`          | 单条审计事件                 |
| 3    | 人工审批 | `/approvals/:approval_id?` | 单条审批请求                 |
| 4    | 证据链   | `/evidence`                | Trace 或用户任务             |
| 5    | 安全评测 | `/evaluation`              | 评测结果与审计窗口指标       |
| 6    | 系统状态 | `/system`                  | 服务、会话、策略与适配器状态 |

`/evidence/:trace_id` 是证据链详情路由，不在主导航中增加重复入口。

人工审批位于证据链之前，因为待审批请求具有时效性并可能阻塞运行时动作。

### 3.2 业务对象边界

- **审计事件**：Guard 记录的一次可独立定位的事实；事件调查列表一行代表一个审计事件。
- **证据链**：同一 `trace_id` 下的一组事件；证据链列表一行代表一个 Trace。
- **审批请求**：等待人工决策的一次动作请求；审批队列一行代表一个 approval。
- **安全告警**：需要用户关注的安全信号，不与所有审计事件互换使用。
- **评测结果**：一次已保存评测及其样本、指标和来源，不与当前审计窗口派生指标混合。

不得用同一套列表重复表示审计事件和证据链。

### 3.3 全局框架

应用框架由以下区域组成：

- 顶部栏：产品名称、全局健康状态、数据更新时间、全局搜索和待审批数量。
- 侧栏：稳定的主导航和当前页面状态。
- 工作区：页面标题、主要操作、页面状态和业务内容。
- 详情层：用于快速检查的右侧面板或用于确认的弹窗。

全局搜索用于定位证据链、资源、规则或事件，不承担结构化筛选职责。

## 4. 页面布局与容器

页面只使用以下主要容器模式：

| 模式          | 用途                           | 主要规则                                   |
| ------------- | ------------------------------ | ------------------------------------------ |
| App Shell     | 顶部栏、侧栏和工作区           | 维持稳定导航与全局状态                     |
| Page Header   | 页面标题、更新时间和主要操作   | 每页只出现一个一级标题                     |
| Summary Strip | 一组同范围、可比较的关键值     | 连续排列，用分隔线区分                     |
| Section       | 同一问题下的一组内容           | 标题、说明、操作与正文保持同一层级         |
| Workspace     | 调查、审批或证据链分栏         | 普通页面跟随文档滚动，明确的分栏再独立滚动 |
| Detail Panel  | 快速查看事件或节点详情         | 不承载完整调查流程                         |
| Inline Notice | 错误、陈旧数据、回退和操作结果 | 靠近受影响内容，说明下一步                 |

### 4.1 Page Header

- 一级标题使用清晰的页面名称，不附加重复的类别副标题。
- 刷新、导出等页面级操作位于标题栏右侧。
- 标题、更新时间和操作在紧凑桌面允许换行，但不得互相覆盖。
- 页面标题可使用品牌主色，标题旁可保留短小的品牌信号轨；不得使用整段渐变文字或与任务无关的图形。

### 4.2 Section

- 区块标题回答“这部分是什么”，辅助说明回答“数据范围或用途是什么”。
- 区块操作与标题同行，主要内容紧随其后。
- 相邻区块使用间距和 1px 分隔线建立层级。
- 同一页面内不得同时使用多套区块标题、边距和操作对齐方式。

### 4.3 Workspace

- 双栏和多栏工作区必须明确主区与辅助区。
- 列表或时间线负责定位，详情区负责解释，独立详情页负责完整调查。
- 普通路由由浏览器文档承担唯一主滚动；只有审批队列、节点检查器、全屏画布等边界明确且需要
  保留上下文的区域可以独立滚动，并使用滚动边界隔离。
- 各滚动区域必须可见、可预测，不得形成页面、工作区和内容面板三层滚动嵌套。
- 固定操作栏不得遮挡最后一行内容或键盘焦点。

## 5. 去卡片化与视觉层级

### 5.1 分组方式

内容分组按以下优先级选择：

1. 语义标题和自然文档流。
2. 间距和网格对齐。
3. 水平或垂直分隔线。
4. 中性背景层。
5. 有明确交互层级时才使用边框、圆角和阴影。

同构、需要比较的数据必须使用表格或结构化列表。指标使用 Summary Strip，属性使用定义列表，长链路使用时间线或图。

### 5.2 禁止的容器模式

不得把页面拼成多个视觉权重相同的圆角盒子，包括：

- 指标卡墙、状态卡墙和健康卡墙。
- 每个图表一个悬浮容器。
- 每条事件、Trace、审批或配置发现项一个大卡片。
- 仅为填充页面而存在的信息框。
- 使用大圆角、阴影或背景色制造没有业务含义的分组。

不得新增 `MetricCard`、`StatusCard`、`ChartCard`、`InfoCard`、`HealthCard` 等以容器外观而非业务语义命名的共享组件。

### 5.3 圆角、阴影和背景

- 按钮、输入框、下拉层、弹窗、抽屉和图节点可以使用现有圆角 token。
- `--radius-pill` 仅用于短小、不可换行的原子状态或数量，不用于内容区和普通按钮。
- 页面区块、表格和定义列表默认不使用悬浮阴影。
- `--shadow-raised` 仅用于弹窗、抽屉、下拉菜单等真实浮层。
- `--shadow-focus` 仅用于键盘焦点。
- Inline Notice 使用中性或语义背景与边线，不使用阴影。
- 页面背景保持中性，不使用大面积彩色光斑、玻璃拟态或多层悬浮表面。

### 5.4 渐变与光效

渐变和光效只用于建立品牌识别、交互反馈或数据焦点，允许范围如下：

- 品牌标识和品牌文字使用石油绿至翡翠绿的短渐变。
- 页面标题信号轨和侧栏选中轨使用同一品牌渐变。
- 导航选中态可从浅品牌背景过渡到透明，不覆盖整行文字。
- 单条数据条可在同一语义色内由浅至深过渡，数据长度仍是主要编码。
- 主图表的面积、选中数据点和实时状态可使用低透明度光晕。
- 新事件到达时可对对应行或数据点进行一次性信号强调。

不得使用：

- 蓝紫渐变或与安全语义无关的多色渐变。
- 每个区块各自使用不同渐变。
- 持续循环的霓虹、扫描线、呼吸光和背景动画。
- 用光效替代焦点、选中、严重性或数据数值。

所有渐变和光效必须由 `_tokens.scss` 中的 token 统一提供，页面不得散落新的十六进制渐变端点。

### 5.5 允许的独立对象

以下对象可以有清晰边界，但不得扩大为卡片墙：

- 弹窗和确认框。
- 右侧详情面板与抽屉。
- 下拉菜单和组合框列表。
- 溯源图节点。
- 错误、警告和回退提示。
- 需要独立坐标系的图表绘图区。

## 6. 色彩、排版、间距与动效

### 6.1 Token

`apps/dashboard/src/styles/_tokens.scss` 是视觉 token 的唯一来源。页面和组件不得另建并行变量体系。

| 类别                              | 使用范围                     |
| --------------------------------- | ---------------------------- |
| `--color-page*`                   | 页面和工作区背景             |
| `--color-surface*`                | 控件、浮层和局部中性背景     |
| `--color-text*`                   | 主文本、辅助文本和弱化文本   |
| `--color-border*`                 | 区块、表格、控件和浮层边界   |
| `--color-link`、`--color-active*` | 链接、选中态和主要交互强调   |
| `--color-success*`                | 正常、有效和成功反馈         |
| `--color-warning*`                | 待处理、陈旧和需要注意的状态 |
| `--color-danger*`                 | 严重风险、系统失败和错误反馈 |
| `--color-focus`                   | 键盘焦点                     |
| `--color-node-*`                  | 溯源图节点类别               |
| `--gradient-*`                    | 品牌、选中轨和单色数据强调   |
| `--glow-*`                        | 焦点、实时信号和选中数据点   |

- 不得在页面样式中散落新的十六进制状态色。
- 品牌强调色不得替代风险、健康或审批状态色。
- 大面积背景保持中性，语义色只强调需要识别的局部信息。

### 6.2 排版

- 拉丁字母和数字优先使用 IBM Plex Sans Variable，中文使用苹方、微软雅黑 UI、Noto Sans CJK SC 等系统字体回退。
- Trace ID、事件 ID、哈希、路径、工具名和结构化值使用 IBM Plex Mono 或系统等宽字体。
- 一级页面标题使用 `--font-size-24` 至 `--font-size-28`。
- 区块标题使用 `--font-size-16` 至 `--font-size-18`。
- 正文、表格和控件以 `--font-size-13` 至 `--font-size-14` 为主。
- 辅助信息不得小于 `--font-size-11`，且必须保持足够对比度。
- 数量、比例、分数和延迟使用 tabular numbers，保持小数精度一致。
- 不使用全大写中文标签；英文缩写仅在业务定义确实需要时保留。

### 6.3 间距与密度

- 间距只使用 `--space-*` token。
- 常规工作区内边距为 `--space-6` 至 `--space-7`，紧凑桌面按现有断点收紧。
- 表格和队列行采用紧凑或标准密度，单行内容高度以快速扫描为目标。
- 同一层级的标题、操作、表格和分页必须共享对齐线。
- 不为单个短值保留大面积空白。

### 6.4 动效

- 路由切换使用 140ms 左右的透明度过渡；离场页面立即退出交互层，不平移整个工作区，不等待离场动画后再展示新页面。
- 抽屉和弹窗使用 160–190ms 的 `transform` 与 `opacity` 过渡，退出反馈可缩短至 90–120ms。
- 图表和数据条更新使用 220–280ms 的 `transform` 插值，不在每次轮询时重新播放整区入场动画。
- 新事件只对对应行或数据点进行一次性信号强调，不移动内容，不改变用户当前滚动位置。
- 自动轮询和页面切换加载不得触发刷新按钮旋转；旋转进度只表示用户主动发起的刷新。
- 动画只使用 `transform` 和 `opacity`，不得使用 `transition: all`，不得过渡宽高、内外边距、位置或其他会触发布局的属性。
- 不使用数字滚动、卡片依次飞入、持续闪烁或循环装饰动画。
- 必须遵守 `prefers-reduced-motion`，停用非必要动画和位移。

### 6.5 数据可视化

图表用于回答趋势、分布、对比、关系和异常定位问题。总览、调查上下文和安全评测可以使用多种互补图表，但不得为了增加数量重复表达同一指标。

- 总览首屏只保留一个主要图表，并同时保留待分诊内容。
- 次级分析区可使用决策趋势、严重性与决策矩阵、攻击类型分布、规则命中 Pareto 和运行时活动小倍数。
- 调查页可使用紧凑事件密度时间轴提供列表上下文，不得替代表格。
- 评测页可使用防护前后斜率图、按攻击类型对比、混淆矩阵和延迟分布。
- 审批页保持操作优先，不加入与当前决策无关的图表。
- 系统页只绘制当前接口或已加载事件能够支持的活动和分布，不伪造历史监控数据。

每个图表必须展示或提供：

- 明确标题、时间范围、样本量、单位和数据来源。
- 加载、空数据、失败、陈旧和局部失败状态。
- 文本摘要、可访问说明或等价数据表。
- 颜色之外的直接标签、线型、图标或纹理。
- 能够进入事件、Trace、样本或筛选结果的明确下钻入口。

简单 Sparkline、数据条和 TopN 优先使用原生 SVG 或 CSS；复杂时间序列、热力矩阵和分布图可使用按需加载的图表能力。图表不得引入接口未提供或无法由已加载数据确定性派生的数值。

## 7. 状态与安全语义

风险严重性、Guard 决策、系统健康、审批状态和审计完整性是不同维度，必须分别表达。

### 7.1 风险严重性

| 数据值     | 显示文案 | 视觉要求                       |
| ---------- | -------- | ------------------------------ |
| `critical` | 严重     | 使用强风险强调，并显示明确原因 |
| `high`     | 高       | 使用风险强调，视觉权重低于严重 |
| `medium`   | 中       | 使用警告语义                   |
| `low`      | 低       | 使用中性语义                   |

- 严重性说明行为可能造成的风险，不说明 Guard 是否正常工作。
- 风险分数必须同时显示严重性或原因，不得作为孤立结论。
- 不生成接口未提供的综合安全分、置信度或健康度。

### 7.2 Guard 决策

| 数据值       | 显示文案     | 语义                     |
| ------------ | ------------ | ------------------------ |
| `allow`      | 允许         | 策略允许动作继续         |
| `ask`        | 需审批       | 动作暂停，等待人工处理   |
| `deny`       | 拒绝         | 策略不授权当前动作       |
| `allow_once` | 人工单次放行 | 仅当前请求获得一次性许可 |

策略决定、干预方式、执行状态、副作用和结果处置必须分开表达。只有运行时回执能够证明动作未被调用时，才可使用“执行前拒绝已确认”或“已阻断”等执行结果文案。`decision=deny` 本身不得推断工具未调用，也不得推断副作用数量为零。人工单次放行也不得显示为普通自动成功。

安全总览的决策摘要只统计当前审计窗口内逻辑唯一的 `policy_evaluation`，分别展示 `allow`、`ask` 和 `deny`，不得把策略拒绝翻译为已经成功阻断。策略介入定义为 `ask + deny`，同时提供独立的策略拒绝率与审批触发率。当前窗口指标只读取原子窗口响应，不从历史聚合或独立评测运行补数。

### 7.3 系统与数据状态

| 数据状态  | 显示含义 | 处理方式                         |
| --------- | -------- | -------------------------------- |
| `online`  | 正常     | 显示最近检查时间                 |
| `offline` | 不可用   | 说明受影响能力和重试方式         |
| `unknown` | 未知     | 不推断为正常或失败               |
| `stale`   | 数据陈旧 | 保留旧数据并显示最后成功更新时间 |
| `loading` | 正在加载 | 保留稳定布局，禁止重复操作       |
| `error`   | 加载失败 | 显示原因和可执行下一步           |

“接口未提供”“尚未检查”“检查中”“正常”和“检查失败”必须使用不同文案。

### 7.4 审计完整性

- `valid: true` 显示“审计链有效”。
- `valid: false` 显示“审计链异常”，并在可用时定位首个异常审计。
- 数据库链状态与外部锚点状态必须分行表达，不能合并成一个 badge。外部锚点 `current` 显示“已同步”，`stale` 显示未锚定事件数，`invalid` 与 `error` 使用异常状态；`disabled` 必须明确显示“未配置”，不能伪装为成功。
- `stale` 只表示签名检查点落后于当前链头，不得改写为审计链异常；`invalid` 表示签名、检查点链或数据库绑定不一致，必须持续可见。
- 系统状态页可展示 JCS 规范化方法、检查点序号、签名检查点哈希、最近锚定时间和非秘密 key ID；不得展示 HMAC 密钥或原始签名材料。
- 尚无结果显示“未验证”或“暂无完整性数据”，不得显示为有效。
- 溯源图可用性不等同于审计链完整性。
- 单条事件的链位置只读取 `AuditEvent.integrity.sequence`、`prev_hash`、`event_hash` 和 `canonicalization`；不得在前端维护 `evidence.audit`、`chain_index`、`entry_hash` 或 `previous_hash` 等平行字段。

### 7.5 状态组件

`StatusBadge` 仅表达一个短小、原子的状态。一个对象存在多个状态维度时，应分列或分行展示，不得把“高危拒绝正常”等信息拼成一个彩色标签。

## 8. 表格、搜索、筛选与导出

### 8.1 表格

需要比较、排序、筛选或持续增长的数据必须使用语义表格。

- 表格使用 `<table>`、`<caption>`、`<thead>`、`<tbody>` 和正确的 `<th>`。
- 列按用户决策顺序排列，不按数据库字段顺序排列。
- 文本左对齐，数字按统一规则右对齐。
- 行之间使用水平分隔线，不使用完整网格和竖向边框。
- Hover、选中和键盘焦点必须可区分。
- 行点击必须具备键盘等价操作，并在详情关闭后恢复焦点。
- 行内操作保持可见，不只在 Hover 时出现。
- 空值优先说明原因；密集数字列无法展开说明时使用 `—`，不得与 `0` 混淆。

### 8.2 搜索与筛选

- 搜索用于定位具体 Trace ID、事件 ID、资源、规则名称、工具或任务文本。
- 筛选用于按决策、严重性、运行时、事件类型、攻击类型和规则缩小数据集。
- 搜索框位于筛选工具栏左侧，常用筛选紧随其后。
- 必须提供清除全部筛选的操作。
- 常用筛选默认直接显示，低频条件进入“更多筛选”。
- 筛选结果数量、默认排序和当前页必须明确。

事件调查筛选状态使用现有 URL query：

```text
search
decision
runtime
severity
event_type
attack_type
blocked
rule
stage
page
event_id
```

证据链列表使用 `search`、`status`、`page`；评测样本定位和分页使用 `case_id`、`case_page`。

URL 中不得写入工具参数、用户任务全文或其他敏感内容。

### 8.3 分页

- 事件调查和证据链列表每页 20 条，评测样本每页 25 条。
- 分页紧邻对应表格，显示当前页和总页数。
- 改变筛选条件后回到第一页。
- 加载新页时不得清空筛选条件。
- 没有更多数据时禁用对应翻页操作。

### 8.4 导出

- 操作名称必须说明范围，例如“导出当前筛选结果”。
- 导出内容与当前筛选和排序保持一致。
- 页面未加载全量结果时，不得让用户误认为导出了全部历史数据。
- 导出保持后端脱敏结果，不包含 CSRF token、长期凭证或内部规则编号。
- 前端生成 CSV 时必须处理公式注入风险。

## 9. 详情面板、长文本与结构化数据

### 9.1 详情层级

- 快速检查单条事件或节点使用 `DetailDrawer`。
- `DetailDrawer` 以固定浮层覆盖工作区，不改变主表格或时间线宽度；关闭过渡完成后恢复触发点焦点。
- 需要完整时间线、溯源关系或多步操作时进入独立页面。
- 表格行不得无限展开复杂证据。
- 弹窗只用于短确认，不承载调查详情。

### 9.2 长文本

| 内容                    | 展示规则                                       |
| ----------------------- | ---------------------------------------------- |
| Trace ID、事件 ID、哈希 | 等宽字体，允许复制，列表中截断，详情中完整显示 |
| 工具名                  | 保持原值，不翻译，不换行                       |
| 路径和资源目标          | 按文本显示，允许断行或中间截断                 |
| 用户任务和判定原因      | 允许换行，不截断关键含义                       |
| 工具参数、日志和错误    | 按不可信文本显示，可折叠但必须可完整查看       |
| 规则                    | 显示可读名称，不显示内部数字编号               |
| 空值                    | 使用“未提供”“尚未记录”“不适用”等准确文案       |

Tooltip 只能补充列表中的完整值，不能承载完成任务所必需的唯一信息。

### 9.3 结构化数据

`StructuredDataView` 只用于次级技术信息：

- 默认先展示经过组织的关键字段。
- 原始结构化内容放在折叠区域。
- 不在页面主区域直接倾倒完整 API 响应。
- 解析失败时按文本安全显示，不得执行内容。

## 10. 页面规范

### 10.1 安全总览

安全总览按以下顺序组织：

1. 全局运行状态：Guard API、数据库、防护链路和审计完整性。
2. 当前审计窗口摘要：事件数、拒绝、需审批和允许。
3. 首屏工作区：一个主要趋势图与最近高风险事件、待审批请求。
4. 次级分析：严重性与决策矩阵、攻击类型、规则命中和运行时活动等互补可视化。

规则：

- 所有派生数量必须标明“当前审计窗口”，并区分审计记录数与逻辑策略评估数。
- 高风险事件采用紧凑表格或结构化行，可直接进入事件或证据链。
- 总览不得复制系统页的完整策略、适配器和配置审计明细。
- 不展示无时间范围的累计调用量、装饰性排行榜、大型仪表盘或自造综合分。
- 首屏图表不得挤压待分诊内容，使其离开主要工作区。
- 次级图表不得重复摘要条已有的孤立数字，每个图表必须提供独立问题、来源和下钻。

### 10.2 事件调查

事件调查是主要生产页面，使用全宽事件表格。

推荐列顺序：

```text
时间
严重性
决策
运行时
事件类型
工具 / 资源目标
原因
用户任务
Trace ID
```

规则：

- 首屏保留时间、严重性、决策、工具/资源和原因。
- 筛选工具栏保持紧凑；攻击类型和规则可进入更多筛选。
- 默认按最新时间排序。
- 点击非操作单元格打开事件详情面板。
- 详情必须展示原因、工具、资源目标、用户任务、可读规则和关联 Trace。
- 只有进入完整任务链路时才跳转 `/evidence/:trace_id`。
- 关闭详情后保留筛选、页码、滚动位置和触发行焦点。

### 10.3 人工审批

桌面使用“待审批队列 + 审批详情”的固定双栏工作区。

768–900px 的平板工作区使用单 Pane 主从布局：`/approvals` 只显示审批队列，
`/approvals/:approval_id` 只显示对应详情并提供“返回审批队列”；深链必须直接恢复对应详情，
不得在窄工作区继续并排挤压队列和审批影响。

队列至少展示：

```text
严重性
工具
资源目标
请求时间或剩余时间
风险分数
```

详情按以下顺序展示：

```text
用户任务
Agent 请求执行的动作
工具与资源目标
关键参数
命中规则
判定原因
放行影响
关联事件与证据链
操作
```

规则：

- “仅本次放行”必须二次确认，并重复工具、资源目标和影响。
- “拒绝授权”与“仅本次放行”使用清晰、完整的动词文案；授权拒绝后的实际执行状态仍以运行时回执为准。
- 提交中禁用两个决策入口，防止重复提交。
- 已过期、已处理或会话失效时不得继续提交。
- 服务端返回请求已终结时，显示终态并刷新队列，不自动重试状态改变请求。
- CSRF token 和原始错误堆栈不得出现在页面、Toast 或复制内容中。
- 不提供永久放行、记住选择或策略编辑入口。

### 10.4 证据链列表与详情

证据链列表一行代表一个 `trace_id`，至少展示任务或 Case 标识、标题、最终状态、最新事件时间和下钻入口。

证据链详情顶部建立上下文：

```text
用户任务或链路标题
最终决策
运行时
开始时间
最近事件时间
Trace ID
审计完整性
```

调查区遵循：

```text
六维事实摘要   = 决策、干预、执行、副作用、结果处置和完整性
四阶段证据流   = 输入信任、上下文意图、工具策略、执行审计
大尺寸溯源图   = 因果关系主视图与节点检查器
审计时间线     = 全部原始记录的等价事实入口
证据档案       = 规则、风险组合、事件时策略和脱敏原始证据
```

规则：

- 时间线和溯源图选择必须同步到同一事件或节点。
- 真实溯源响应中的 `ref_id` 保留后端原始实体 ID；审计节点使用原始 `audit_id` 与时间线事件联动，不要求或补造 `event:` 前缀。
- 真实关系值 `evaluated_to`、`recorded_as`、`reviewed_by` 在展示层映射为简短中文关系词；节点风险元数据读取接口字段 `risk_score`，Mock 数据不得重新定义真实接口契约。
- 选择溯源节点时递归突出全部祖先、全部后代和路径边，弱化无关关系。
- 超过 24 个节点时可默认展开关键攻击路径并收拢旁支；必须显示隐藏节点数，并提供展开完整关系的入口。
- 生命周期区域和非关键支路可以折叠；搜索或 URL 定位到隐藏节点时必须自动恢复该节点所在区域。
- 节点展示事件类型、动作、决策和时间，不展示未采集的内部推理。
- 图节点使用固定宽高和多行截断，完整信息进入证据面板。
- 节点必须具有类型图标、文字类型、标题、摘要和证据状态；颜色不得作为唯一类型编码。
- 因果、检测、策略、审批、执行和审计关系使用不同线型及简短文字；边标签只在聚焦、悬停或足够缩放时显示，且不能覆盖节点内容。
- 图提供 Minimap、全屏、缩放复位、适配画布、节点搜索、类型筛选和生命周期区域控制。
- 桌面采用从左向右的分层因果布局，紧凑视口切换为从上向下；自动布局失败时使用确定性分层回退。
- 大图布局异步执行并按图摘要缓存；ELK 自动布局在独立模块 Worker 中运行，组件卸载时释放 Worker；动效遵守 `prefers-reduced-motion`。
- 原始 JSON 只作为折叠的次级信息。
- Trace 详情接口失败且存在窗口事件时，必须说明当前只展示已加载审计窗口内的匹配事件，链路可能不完整。
- 溯源接口失败只替换图区域，时间线仍可查看并提供独立重试。
- 详情先以紧凑 Trace 摘要展示当前已确认结论，随后立即提供执行轨迹、溯源关系和审计记录
  三个视图；六维事实和四阶段证据流进入工作区后的折叠“调查摘要”，按需展开。
- 溯源图及其布局依赖按需加载并预留稳定高度，不得阻塞结论和事实摘要渲染。

#### 10.4.1 运行时安全观测

2026-08-07 已冻结、2026-08-08 已完成 Dashboard 实施，详见
[Agent 运行时安全可观测与动态治理设计](runtime_safety_observability_design.md)。真实
LangGraph 的 Memory/PostgreSQL 演示链与 Dashboard PostgreSQL API 读链已经通过独立联调
门禁。

不新增一级页面，`/evidence/:trace_id` 在紧凑 Trace 摘要之后直接提供三个联动视图：

```text
执行轨迹 | 溯源关系 | 审计记录
```

- 执行轨迹默认展示全部已持久化 Guard 运行阶段；有 `action_id` 的记录按动作聚合策略判断、
  审批、开始观察、工具结果检查和运行结果，没有 `action_id` 的策略事件按 `event_id` 显示为
  独立检查点。
- 执行轨迹默认使用确定性图形视图，并提供信息等价的列表视图；视图模式使用
  `execution_layout=graph|list` 恢复，默认值 `graph` 不写入 URL。
- 图形视图按“智能体处理、受控动作、检查与结果”组织泳道，每一个
  `ExecutionStepViewModel` 只生成一个节点；动作生命周期更新同一节点，不拆成重复动作。
- 执行轨迹只连接相邻审计顺序，边标注为“随后记录”，不得把时间先后声称为因果关系，也
  不根据事件名称、时间接近或布局位置猜测分支。
- 上下文组装、模型输入、模型输出、工具调用、工具结果、记忆写入和消息发送等当前支持的
  GuardEvent 都必须出现；“读取记忆 / 执行代码”只可作为代表性回归场景，不得实现为动作
  白名单。Trace 生命周期和配置审计不冒充 Agent 运行步骤。
- 溯源关系解释因果与安全依据，不随每次轮询自动重排。
- 审计记录按 AuditEvent 保留完整时间顺序和原始证据入口。
- 点击运行步骤可定位对应的 action、context、model intent、event、decision 或 audit 节点，
  也可打开对应审计记录；反向选择必须通过原始稳定 ID 同步。
- 视图、轨迹布局和选择分别使用 `view`、`execution_layout`、`action_id`、`node_id`、
  `event_id` query 恢复；旧
  `event_id` 深链继续有效。
- 决策使用允许、需审批、拒绝语义；运行状态另用图标和文字表达，不能复用同一颜色含义。
- 原始 `ask` 在审批放行后仍保留；单次放行和已执行作为独立事实显示。
- 只有明确 `tool_call_started` 或等价 observation 才显示“正在执行”。
- 不显示未来动作、百分比进度或模型隐藏思维链。
- 执行轨迹使用独立 step 投影组件：动作生命周期折叠为一个步骤，非动作安全阶段保持检查点；
  现有事件时间线作为审计记录组件，不把逐条 AuditEvent 与步骤聚合混成同一层级。
- 搜索和筛选只弱化不匹配的图节点，不删除并重连审计顺序；列表模式可以只列出匹配步骤。
- 当前步骤、新增步骤和状态变化只更新节点强调，不触发布局重排；大 Trace 使用可见区域渲染、
  Minimap 和当前步骤聚焦，不能用压缩到不可读的全图作为唯一入口。
- 普通模式下滚轮继续滚动页面，图缩放使用控件；只有全屏画布接管滚轮缩放。步骤检查器是
  边界明确的辅助滚动区，紧凑视口改回自然文档流。
- 自动更新不得抢夺滚动位置或焦点；普通新增只显示可主动查看的更新提示，待审批、拒绝和
  执行失败才使用克制的 `aria-live` 播报。

运行 Trace 采用条件轮询；页面不可见时暂停。收到明确 Trace 终态后停止循环，并强制执行
一次 Trace 最终对账和一次 Provenance 校准；缺失的审批或运行回执保持“未确认”，不因停止
轮询补造结果。Provenance 也可在进入视图、用户请求查看安全依据或主动更新时校准，并保留
筛选、折叠、选择和可恢复的视口锚点。

### 10.5 安全评测

页面分成两个数据区：

1. 最新完整评测：评测时间、数据集、样本量、防护前后攻击成功率、按攻击类型结果和样本证据。
2. 当前审计窗口指标：逻辑策略评估数、策略介入率、策略误报率、策略漏报率、判定延迟、策略介入混淆矩阵和运行时判定延迟对比。

每个指标必须提供：

```text
指标名称
定义或分子 / 分母
数据来源
时间范围
样本数量
单位和精度
```

规则：

- 防护前后任一数据缺失时，不展示不完整的攻击成功率比较。
- 当前窗口只统计逻辑唯一 `policy_evaluation`；runtime outcome、observation 和 config audit 不增加策略计数。
- 策略介入率以 `ask + deny` 为分子；策略拒绝率与审批触发率分别以 `deny`、`ask` 为分子。
- 策略 FPR/FNR 只使用有已知策略决定和恶意性标注的评估，并显示对应分母。
- 混淆矩阵必须明确标注为策略介入口径，使用“介入 / 未介入”列，不使用“实际阻断”列；颜色只是辅助。
- 判定延迟只统计策略评估阶段，运行时结果处理耗时不得混入。
- 当前窗口必须展示返回审计记录数、逻辑策略评估数、观察时间范围和可用的完整性状态；后端未提供 `has_more` 时保持未知。
- 历史聚合只有在接口提供明确时间范围、去重方式和分母后才能进入独立区域，不得作为当前窗口或评测运行的回退数据。
- 延迟对比使用水平条形图或表格，不使用仪表盘。
- 图表只回答趋势、分布或对比问题，不承担装饰作用。
- 样本必须能够下钻到关联 Trace。

### 10.6 系统状态

系统状态按用户问题纵向组织：

1. Guard API 与数据库是否可用。
2. 浏览器会话和审计轮询是否正常。
3. 审计数据是否可信。
4. 当前策略是否正常加载。
5. OpenClaw 适配器是否在线并完成必要 Hook。
6. 配置审计是否存在发现项。

规则：

- 服务和属性使用状态行、定义列表或表格，不使用卡片网格。
- 每个状态展示最近检查或更新时间。
- 策略、适配器和配置审计接口独立失败时，只影响对应区块。
- 配置发现项按严重性、目标、主体、运行时和时间组织，证据按需展开。
- 页面保持只读，不提供策略修改、服务重启、凭证管理或启动链接生成操作。

## 11. 加载、刷新、错误与局部降级

### 11.1 应用启动

| 前端状态        | 页面行为                                                 |
| --------------- | -------------------------------------------------------- |
| `idle`          | 准备建立 browser session，不渲染业务页面                 |
| `loading`       | 显示稳定的会话加载状态                                   |
| `authenticated` | 加载并显示业务数据                                       |
| `error`         | 说明会话或启动链接问题，并引导用户通过 launcher 重新打开 |

会话失败不得显示项目不存在的登录表单。

### 11.2 数据区块

| 状态      | 页面行为                               |
| --------- | -------------------------------------- |
| `idle`    | 尚未开始加载                           |
| `loading` | 首次加载时显示骨架，保留稳定尺寸       |
| `ready`   | 显示内容和最后成功更新时间             |
| `stale`   | 保留旧内容并显示数据陈旧提示           |
| `error`   | 无可用内容时显示错误和重试             |
| empty     | 接口成功但没有数据，说明原因或下一步   |
| partial   | 只在失败区块显示提示，其他内容继续可用 |

- 刷新已有内容时不得用全屏骨架替换旧数据。
- 某一接口失败不得清空其他接口的旧数据。
- 错误文案必须说明发生了什么、受影响内容和用户可执行的下一步。
- 禁用状态必须说明原因，不得只降低透明度。
- 路由切换优先复用 10 秒轮询窗口内已经成功加载的共享资源，只请求目标页面尚未加载或已过期的数据。
- 用户主动刷新和页面从隐藏恢复可见时强制检查当前页面所需资源；页面级刷新进度只对应用户主动刷新。
- 页面更新时间取当前页面必需资源中最早的成功更新时间，避免用局部新数据掩盖其他陈旧数据。

### 11.3 审批提交

审批提交必须覆盖：

```text
idle
submitting
succeeded
conflict
failed
```

- `submitting`：禁用重复提交并显示进度。
- `succeeded`：显示明确结果并同步队列和证据链。
- `conflict`：显示已由其他端处理、已过期或状态已终结，不重复提交。
- `failed`：保留当前上下文和证据，允许用户在状态仍有效时重试。

### 11.4 轮询

- 页面可见时沿用每 10 秒串行刷新。
- 页面隐藏时暂停轮询，恢复可见后立即刷新。
- 显示最后一次成功更新时间，而不是最后一次尝试时间。
- 新事件不得突然改变用户当前滚动位置。
- 用户停留在旧位置时，以“有新事件”提示替代强制插入。
- 同一 `event_id` 不得重复加入列表。
- 筛选变化后，旧请求不得覆盖新条件的结果。
- 审批提交前必须再次以服务端结果为准确认请求仍可处理。

## 12. 文案与术语

### 12.1 统一术语

| 数据或概念       | 用户可见文案   |
| ---------------- | -------------- |
| audit event      | 审计事件       |
| alert            | 安全告警       |
| trace            | 证据链         |
| provenance       | 溯源关系       |
| policy           | 安全策略       |
| rule hit         | 命中规则       |
| runtime          | 运行时         |
| adapter          | 运行时适配器   |
| approval         | 审批请求       |
| resource target  | 资源目标       |
| integrity        | 审计完整性     |
| config finding   | 配置审计发现项 |
| evaluation       | 安全评测       |
| false positive   | 误报           |
| false negative   | 漏报           |
| decision latency | 判定延迟       |

同一概念不得在不同页面使用不同叫法。枚举到中文文案的映射集中在 formatter 或领域工具函数中，不得由页面各自解释。

### 12.2 文案规则

- 标题直接描述对象或任务，例如“事件调查”“审计链完整性”。
- 按钮使用明确动词，例如“导出当前筛选结果”“仅本次放行”。
- 状态文案描述当前事实，不写模糊的“有问题”“异常情况”。
- 错误文案不回显凭证、完整请求、内部堆栈或数据库信息。
- 页面不得出现 Mock、Coming Soon、开发注释、布局解释或视觉策略。
- 不使用夸张、拟人化或营销式文案描述安全能力。

## 13. 无障碍

以下要求是页面完成标准：

- 点击操作使用 `<button>`，导航使用链接或 `RouterLink`。
- 表单控件具有可见标签或等价 accessible name。
- 所有交互可通过键盘完成，焦点状态始终可见。
- 普通文本对比度至少为 4.5:1，大文本至少为 3:1。
- 交互目标至少为 24×24 CSS px，或具有足够间距。
- 模态弹窗打开后管理焦点并形成焦点闭环，支持 Esc 关闭，并在关闭后恢复触发点焦点。
- 桌面详情面板不得无故阻断主工作区；打开、关闭和返回触发点必须具有稳定键盘路径。
- 表单和操作错误使用文本说明，并与相关控件建立关联。
- 颜色不得作为严重性、决策、健康或完整性的唯一载体。
- 溯源图不得成为唯一证据表达，时间线必须提供等价事实。
- 图表关键数据必须能通过标签、文本摘要、表格或可访问说明获得。
- 可检查的趋势图使用单一键盘焦点，并通过方向键切换时间点；不得为每个数据点制造独立 Tab 停靠点。
- `aria-live` 只播报审批结果和严重错误等直接影响操作的变化，不连续播报轮询事件。

优先使用原生 HTML 语义，不用 ARIA 模拟原生控件。

## 14. 平板、桌面适配与性能

### 14.1 视口

- 768×1024 是最低平板竖屏基线。
- 820×1180 是常见平板竖屏工作区。
- 1024×768 是平板横屏基线。
- 1180×820 是宽平板工作区。
- 1199×900 是平板与桌面布局切换边界。
- 1280×720 是紧凑桌面工作区。
- 1366×768 是主要最低桌面基线。
- 1440×900 是标准桌面工作区。
- 1920×1080 是宽屏桌面工作区。
- 正式支持 768px 及以上视口；页面根节点在全部支持档位不得产生横向溢出。
- 小于 768px 当前不属于正式支持范围，不得以根最小宽度反向破坏 768px 基线。

### 14.2 布局变化

- 768–1199px 保留图标导航 Rail；展开完整导航时使用非模态覆盖层，不重新压缩工作区，
  支持点击外部区域、导航目标和 `Escape` 关闭并保持稳定焦点路径。
- 768–900px 顶部栏分为两行：品牌、全局健康和待审批位于第一行，全局搜索占第二行；
  901–1199px 使用紧凑单行顶部栏，不隐藏健康异常、更新时间或待审批数量。
- 平板页面按实际容器宽度重排：主次分析区在空间不足时改为单列，筛选器自动换为 2–3 列，
  审批使用队列/详情单 Pane 切换，图形工作台及其检查器不得并排挤压。
- 平板表格保留语义表格和比较关系，仅由表格容器承担横向滚动；页面根节点不得横向滚动，
  不把每一行改造成装饰性卡片。
- 1280×720 优先收紧页边距、区块间距和低频操作，不降低表格与证据文字的可读性。
- 1200px 及以上侧栏始终保留桌面导航，可由用户在展开和折叠状态之间切换。
- 审批保持队列和详情双栏，队列宽度在紧凑桌面适度收窄。
- 当前证据链详情依次展示紧凑结论和三视图调查工作区；六维事实与四阶段证据流位于工作区后
  的折叠“调查摘要”。执行轨迹图或溯源图与检查器在宽桌面并排，紧凑桌面纵向排列，审计
  时间线和证据档案位于等价证据视图。
- 运行时安全观测目标实施后，三个联动视图在四档桌面均保持单一主工作区；紧凑桌面不并排挤压执行轨迹和溯源图。
- 1920×1080 增加并排分析和列间距，不无限拉长说明文字。
- 表格优先保留比较关系；必要时只在表格容器内横向滚动。
- 核心列优先保留，次要字段进入详情，不把每一行转换成装饰性卡片。
- 任何桌面档位不得隐藏判定原因、风险信息或审批影响。

常规布局优先使用 Grid、Flexbox、媒体查询、`minmax()` 和 `clamp()`。只有图表、图布局、拖拽分栏或虚拟列表等确实需要真实尺寸时才使用 JavaScript 测量。

### 14.3 性能

- 路由页面保持懒加载。
- 主导航目标在指针或键盘聚焦时预加载，认证与首屏数据稳定后可在浏览器空闲时预加载其余主页面；不得阻塞首次可用。
- 大表格使用分页、按需加载或虚拟化，不一次渲染无上限数据。
- 图表和异步内容预留稳定尺寸，避免布局跳动。
- 溯源图组件与 ELK 自动布局必须拆分为独立异步资源；ELK 在模块 Worker 中执行，不得重新合并进溯源图主线程 chunk。
- 复杂统计和大 JSON 解析不得在模板渲染阶段重复执行。
- 轮询、滚动和尺寸事件不得触发无节制重计算。
- 不为装饰效果增加大型依赖。
- 日志、样本和原始结构化数据按需展开。

## 15. 前端安全边界

鉴权实现以 [AgentGuard Vue Dashboard 鉴权方案](../07_auth/前端鉴权建议.md) 为准。本规范只约束对应的 UI 行为。

- Dashboard 只处理 HttpOnly browser session 和内存中的 CSRF token。
- `launch_code` 换取会话后立即从地址栏移除，不写入日志或持久化存储。
- 长期凭证、session id 和 CSRF token 不得显示、复制或写入浏览器持久化存储。
- 工具参数、用户任务、日志、路径、错误和后端文本一律按不可信文本渲染。
- 不使用 `v-html` 渲染事件、日志、报告或错误信息。
- URL 和路径默认显示为文本，只有经过明确校验的产品内路由才能生成链接。
- 前端保持后端脱敏结果，复制、详情和导出不得恢复被遮盖字段。
- 内部 `rule_hits` 编号只用于筛选和接口传参，页面与导出只显示可读规则名称。
- 状态改变请求失败时不自动重复提交。
- 权限和审批有效性以后端结果为准，前端禁用只用于防错和反馈。

## 16. 组件、类型与样式约束

### 16.1 共享组件边界

| 组件                 | 规范用途                                 |
| -------------------- | ---------------------------------------- |
| `MetricStrip`        | 同一数据范围内的连续摘要项               |
| `StatusBadge`        | 单一、短小的原子状态                     |
| `DetailDrawer`       | 单条事件或节点的快速检查                 |
| `ConfirmDialog`      | 具有影响说明的短确认和提交状态           |
| `InlineNotice`       | 局部失败、陈旧数据、回退和操作结果       |
| `ChartFrame`         | 图表标题、范围、正文、等价数据和下钻结构 |
| `AppSelect`          | 结构化单值筛选                           |
| `DataFreshness`      | 最后成功更新时间和刷新状态               |
| `LoadingState`       | 首次加载或无旧数据时的稳定骨架           |
| `ErrorState`         | 无可用内容时的错误与重试                 |
| `EmptyState`         | 请求成功但无数据时的解释与下一步         |
| `StructuredDataView` | 折叠的次级结构化信息                     |

- 新共享组件必须有稳定业务语义，不以局部外观命名。
- 相同状态和交互不得在多个页面复制不同实现。
- 局部实现只在不会重复且抽取不能降低总代码量时保留。
- 修改共享组件前必须搜索全部调用并验证不同页面状态。

### 16.2 类型和数据契约

- 页面依赖 `types/dashboard.ts` 中的领域类型，不猜测接口字段。
- 原始 API 数据通过 API mapper 收敛后再进入页面。
- 未知结构使用 `unknown` 并在边界收窄，不使用显式 `any` 绕过检查。
- 可为空字段必须显式处理，不使用无依据的非空断言。
- 决策、严重性、时间、比例、规则名称和空值使用集中 formatter。
- 页面不得自行修改后端字段含义或补造缺失事实。

### 16.3 样式

- 全局样式只承载 token、基础元素和跨页面工具类。
- 页面与组件样式保持 scoped，避免深层选择器覆盖其他组件内部结构。
- 新样式优先复用现有 token 和布局模式。
- 不为单页硬编码重复按钮、状态、表格或弹窗样式。
- z-index 只用于已定义的顶部栏、侧栏、下拉层、抽屉、弹窗和全局提示层级。

## 17. 页面验收清单

修改或新增 Dashboard UI 时逐项确认：

### 信息与任务

- 页面标题、主要对象、数据范围和下一步操作明确。
- 用户能够定位原因、规则、资源目标和关联证据。
- 页面没有与当前任务无关的统计、说明或装饰。

### 布局与视觉

- 没有卡片墙、白名单外渐变或内容区悬浮阴影。
- 同构数据使用表格或结构化列表。
- 标题、分隔线、间距和对齐建立了清晰层级。
- 风险、决策、健康、审批和完整性没有混用状态语义。
- 五档平板与四档桌面工作区均保持核心任务可见、可读和可操作。

### 状态与数据

- 覆盖首次加载、刷新、空数据、失败、陈旧和局部失败。
- 刷新保留旧数据，局部错误不清空整个页面。
- Trace 和溯源接口失败各自独立降级。
- 审批覆盖提交、成功、冲突、失败和过期。

### 交互与内容

- 搜索、筛选、分页和详情返回后保留上下文。
- 长文本、ID、路径和日志不会挤压或丢失关键含义。
- 危险或放行动作展示影响并防止重复提交。
- 所有交互具有键盘路径和可见焦点。

### 安全与工程

- 用户可见内容按不可信文本处理。
- 页面、日志和导出不包含长期凭证、CSRF token 或内部规则编号。
- 组件、类型、formatter 和 token 得到复用。
- 验证范围按仓库根目录 [AGENTS.md](../../AGENTS.md) 的 Dashboard 检查流程执行。
