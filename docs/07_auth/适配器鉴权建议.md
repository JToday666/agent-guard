# AgentGuard Adapter 鉴权方案

## 1. 边界

P0 使用一个静态 adapter token：

```text
AGENTGUARD_ADAPTER_TOKEN
```

Adapter 只通过 `Authorization: Bearer <AGENTGUARD_ADAPTER_TOKEN>` 调用 Guard API。它不使用 browser session、CSRF token、launch code 或 approval nonce，也不能批准自己的高危请求，不能读取 Dashboard/CLI 只读查询接口。

## 2. Token 配置

Guard API 从运行环境读取 adapter token：

```env
AGENTGUARD_ADAPTER_TOKEN=ag_adapter_xxx
```

开发环境提供默认演示值。当 `AGENTGUARD_ENV=production` 时，如果 adapter token、control token 或数据库 URL 仍为默认值，Guard API 拒绝启动。

当前没有 adapter token 初始化 CLI、凭证数据库、轮换或撤销流程。Token 只由 Guard API 进程环境提供，不写入 Control Plane 数据库。

## 3. Scope 和接口

adapter 的固定 scopes：

```text
event:evaluate
event:audit:write
approval:wait
```

| 接口                                   | Scope               |
| -------------------------------------- | ------------------- |
| `POST /v1/guard/evaluate`              | `event:evaluate`    |
| `POST /v1/audit/events`                | `event:audit:write` |
| `GET /v1/approvals/{approval_id}/wait` | `approval:wait`     |

adapter 不具有 `approval:resolve`、`auth:launch`、`audit:read`、`metrics:read`、`trace:read`、`policy:read` 或 Dashboard/CLI 只读权限。

## 4. Bearer 校验

`CapabilityAuthService.verify_bearer()` 执行：

```text
读取 Authorization header
→ 校验 Bearer 前缀
→ constant-time compare 匹配配置的 adapter/control token
→ 构造固定 AuthContext
→ 校验接口所需 scope
```

adapter 匹配后生成：

```python
AuthContext(
    principal_type="component",
    principal_id="cred_adapter_main",
    role="adapter",
    scopes=["event:evaluate", "event:audit:write", "approval:wait"],
    auth_method="bearer",
    runtime="langgraph",
    agent_id="main",
)
```

`runtime` 和 `agent_id` 当前是固定审计标识，不是强隔离边界。

## 5. Approval Wait

Guard API 创建 approval 时记录 `requesting_principal_id`、`trace_id`、`tool_call_id`、`runtime` 和 `agent_id`。Adapter 请求 wait 时，Guard API 校验 approval 由当前 principal 创建，因此 adapter 不能枚举 pending approval，不能等待无关 approval，不能 resolve approval。

## 6. 错误与安全底线

| 场景                     | 响应                |
| ------------------------ | ------------------- |
| 未提供 Authorization     | `401 AUTH_MISSING`  |
| Bearer 格式或 token 无效 | `401 TOKEN_INVALID` |
| Scope 不足               | `403 SCOPE_DENIED`  |

Authorization header 和 adapter token 不得出现在日志、审计事件、Dashboard、前端 env 或持久化产物中。

## 7. P0 不做

```text
适配器登录
动态适配器注册
每个请求签名
每个 agent 默认独立 token
每个 runtime 默认独立 token
远程适配器接入
复杂外部认证协议
适配器 token 管理 UI
mTLS
OAuth
JWT
```

## 8. P1 扩展

P1：每个 `runtime + agent_id` 使用独立 adapter token：

```text
tok_adapter_langgraph_main
tok_adapter_openclaw_main
tok_adapter_openclaw_main
tok_adapter_langgraph_eval_agent_001
```

P1 扩展不得改变业务接口的 scope 校验方式，只扩展 `AuthContext` 中的 `runtime` 与 `agent_id` 绑定规则。
