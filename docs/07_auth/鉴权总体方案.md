# AgentGuard 统一鉴权管理方案

## 1. 核心边界

AgentGuard 使用本地 Capability Auth，不实现用户账号登录。三类调用方拥有相互隔离的凭证和能力：

| 调用方           | 凭证                              | 用途                                                   |
| ---------------- | --------------------------------- | ------------------------------------------------------ |
| CLI / Launcher   | control token                     | 启动管理会话、查询和修改控制面、管理 adapter credential |
| Adapter / Plugin | 数据库注册的 runtime credential   | 评估事件、写运行时回执、等待审批、报告自身状态           |
| Vue Dashboard    | HttpOnly browser session + CSRF   | 读取监督数据并执行人工审批和策略变更                     |

审批 resolve 使用 browser session 与 CSRF，服务端通过数据库原子状态转换防止重复处理。control token 和 adapter token 均不得进入浏览器。

## 2. 角色与 Scope

Control token 生成固定 `control` 上下文，包含启动、查询、策略、评测、适配器状态和凭证管理 scopes。Adapter credential 生成固定 `adapter` 上下文：

```text
event:evaluate
event:audit:write
approval:wait
adapter:status:write
```

Adapter 不能自选角色或 scopes，不具有审批 resolve、控制面读取或凭证管理能力。Browser session 不转换成可外发的 bearer token。

## 3. 接口鉴权

| 接口                                       | 鉴权                                                     |
| ------------------------------------------ | -------------------------------------------------------- |
| `GET /health`                              | 无                                                       |
| `POST /v1/auth/browser/launch`             | control token + `auth:launch`                            |
| `POST /v1/auth/browser/exchange`           | 一次性 launch code                                       |
| `GET /v1/auth/browser/me`                  | browser session                                          |
| `POST /v1/auth/browser/logout`             | browser session                                          |
| `POST /v1/guard/evaluate`                  | runtime credential + `event:evaluate` + runtime/agent 绑定 |
| `POST /v1/config-audit/evaluate`           | runtime credential + `event:evaluate` + runtime/agent 绑定 |
| `POST /v1/audit/events`                    | runtime credential + `event:audit:write` + runtime 绑定   |
| `GET /v1/approvals/{approval_id}/wait`     | runtime credential + `approval:wait` + 主体/身份绑定       |
| `PUT/POST /v1/adapters/{runtime}/...`      | control 或绑定的 runtime credential                       |
| `GET /v1/audit/window`                     | browser session 或同时具备 `audit:read` 与 `metrics:read` |
| 历史指标、Trace、策略读取接口          | browser session 或对应 control scope                     |
| `GET /v1/approvals/pending`                | browser session                                          |
| `POST /v1/approvals/{approval_id}/resolve` | browser session + CSRF                                   |
| `POST/GET /v1/credentials`、撤销接口       | 对应 `credential:*` control scope                        |

## 4. 长期凭证

Guard API 只从环境读取 control token：

```env
AGENTGUARD_CONTROL_TOKEN=ag_control_xxx
```

生产环境若仍使用默认 control token 或默认数据库 URL，Guard API 拒绝启动。

Adapter token 由运行中的 Control Plane 签发：

```bash
uv run agentguardctl credential issue --runtime openclaw --agent-id main
```

Guard API 在 `credentials` 表中保存 token hash、固定 profile、`principal_id`、`runtime`、`agent_id`、签发/过期/撤销时间。完整 token 只在签发响应出现一次；`credential list`、Dashboard、日志和审计均不返回 token hash。消费端仍可使用 `AGENTGUARD_ADAPTER_TOKEN` 注入该 token，但 Guard API 不读取该变量来建立静态身份。

## 5. Launch Code 与 Browser Session

Control token 通过 `POST /v1/auth/browser/launch` 创建默认有效 300 秒、只能消费一次的 launch code；服务端只保存其 SHA-256 hash。

Dashboard 调用 exchange 后，Guard API 创建默认有效 3600 秒的 browser session，以 `HttpOnly; SameSite=Strict; Path=/` 写入 cookie，并返回只保存在前端内存中的 CSRF token。logout 撤销服务端 session 并删除 cookie。

## 6. CSRF 与审批状态机

人工 resolve 的处理顺序为：验证 browser session → 验证 CSRF → 检查允许的决策选项 → 在数据库事务内锁定审批行 → 从未过期 pending 原子转换为 `allow_once` 或 `deny`。

审批状态由 `resolved_at` 和 `expires_at` 派生；读取接口不修改数据库。并发或重复 resolve 只有一个请求成功，其余返回 `409`，不得覆盖首次终态。

## 7. 存储与失效

| 状态               | 存储                                   | 失效条件                 |
| ------------------ | -------------------------------------- | ------------------------ |
| control token      | Guard API 进程环境                     | 运维替换并重启           |
| adapter credential | PostgreSQL 中的 token hash 与身份元数据 | 过期或显式撤销           |
| launch code        | PostgreSQL 中的 hash                   | 消费或过期               |
| browser session    | PostgreSQL 中的 hash 与会话字段         | logout、撤销或过期       |
| CSRF token         | browser session 记录                   | session 失效             |

## 8. 主要错误码

| 场景                         | 状态码 | 错误码                             |
| ---------------------------- | ------ | ---------------------------------- |
| 缺少 Authorization           | `401`  | `AUTH_MISSING`                     |
| token 无效、过期或已撤销     | `401`  | `TOKEN_INVALID`                    |
| Scope 不足                   | `403`  | `SCOPE_DENIED`                     |
| runtime/agent 身份不匹配     | `403`  | `RUNTIME_IDENTITY_MISMATCH`        |
| Session 无效或过期           | `401`  | `SESSION_INVALID` / `SESSION_EXPIRED` |
| Launch code 无效或过期       | `401`  | `LAUNCH_CODE_INVALID` / `LAUNCH_CODE_EXPIRED` |
| CSRF 失败                    | `403`  | `CSRF_INVALID`                     |
| Approval 已过期              | `409`  | `APPROVAL_EXPIRED`                 |
| Approval 已处理              | `409`  | `APPROVAL_ALREADY_RESOLVED`        |
| Credential 不存在            | `404`  | `CREDENTIAL_NOT_FOUND`             |

任何完整 token、launch code、session id、CSRF token、Cookie 或 Authorization header 都不得写入日志、审计事件或前端持久化存储。

## 9. 不在当前范围

当前不提供用户注册、多租户、OAuth/SSO、JWT、mTLS、每请求签名、Dashboard 凭证管理 UI 或远程身份联合。生产部署必须补充 TLS、网络隔离、数据库备份和外部密钥管理。
