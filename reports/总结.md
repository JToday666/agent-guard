# 总结

## 工作总结

AgentGuard 围绕工具增强型 LLM Agent 的运行时行为安全，完成了一套从事件采集、规则检测、三态决策、人工审批、审计溯源到攻击评测的系统原型。与只关注模型文本输出的安全方案不同，AgentGuard 将重点放在工具调用、消息发送、长期记忆、工具结果持久化和外部副作用控制上，目标是在高风险动作真正执行前给出可解释的安全判断。

当前实现中，`agentguard-core` 作为无状态判定内核，定义 7 类事件类型，默认组合 10 类检测器和 11 个主要规则入口，并通过 `allow`、`deny`、`ask` 输出分级决策。Guard API / Control Plane 承担鉴权、策略快照、审批、审计、指标、adapter 状态和 trace 查询等状态能力。LangGraph 侧通过 `SecureToolNode` 与 `GuardedToolGateway` 实现工具执行前拦截；OpenClaw 侧通过 hook-only 插件接入 16 个 hook；Dashboard 提供审批、证据、评测和系统状态展示；AttackBench 提供面向行为副作用的攻击评测框架。

## 主要贡献

1. 建立了面向 Agent 运行时行为的事件契约，将不同 runtime 的工具调用、上下文、模型输入输出、工具结果、记忆写入和消息发送统一为 `GuardEvent`。
2. 实现了确定性、可解释、低依赖的无状态判定内核，能够基于工具画像、资源派生、策略 marker 和任务一致性规则输出三态决策。
3. 将人工审批作为运行时安全闭环的一部分，通过 approval nonce、CSRF、session 和 principal 校验降低审批绕过风险。
4. 为审计记录提供 provenance graph 和 hash chain，使阻断、审批和证据展示具备可追踪性。
5. 构建了 AttackBench 评测框架，使防御效果可以围绕真实副作用、良性误拦截和任务成功率进行量化。
6. 通过 LangGraph 和 OpenClaw 适配验证了架构的跨运行时接入潜力。

## 当前不足

当前实现仍存在明确边界。检测器以规则和启发式匹配为主，对高度混淆、语义改写和跨轮隐蔽攻击的覆盖有限；任务一致性检测尚未引入语义层理解；`ask` 决策依赖人工响应，在高并发或无人值守场景下可能影响可用性；AttackBench 的最终量化指标仍需重新运行后填入；OpenClaw 插件当前不做参数改写、消息改写或原生审批 UI 接管。

因此，报告中不应将 AgentGuard 表述为覆盖所有 Agent 安全风险的成熟生产系统，而应定位为一个以运行时行为监督为核心、具备完整工程链路和评测框架的安全原型。

## 后续工作

后续可从四个方向继续完善：

- 扩展检测能力：在保持可解释性的前提下，引入轻量语义相似度、上下文历史聚合和更细粒度的业务策略。
- 扩展评测数据：补充中文、多行业、多轮会话和真实业务系统中的攻击/良性样本。
- 完善审批与策略运营：支持更灵活的审批策略、批量处理、超时策略和策略变更审计。
- 强化部署安全：结合沙箱、最小权限、密钥管理、网络隔离和多租户隔离，形成更完整的生产部署方案。

总体来看，AgentGuard 的价值在于把 Agent 安全从单点文本过滤扩展为运行时行为控制，并把检测、审批、审计、证据和评测串联成可展示、可复查、可继续演进的系统闭环。
