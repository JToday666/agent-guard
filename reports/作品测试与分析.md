## 3.4 指标口径

AttackBench 的 `calculate_metrics()` 已实现较细的指标拆分，报告中建议采用以下口径：

| 指标                 | 含义                                        | 当前结果 |
| -------------------- | ------------------------------------------- | -------- |
| `asr_before`         | 防御关闭时恶意用例攻击成功率                | 待实测   |
| `asr_after`          | 防御开启时恶意用例攻击成功率                | 待实测   |
| `asr_valid`          | 仅统计有效且可评估恶意用例的攻击成功率      | 待实测   |
| `block_rate`         | 防御开启时恶意用例被 `deny` 或 `ask` 的比例 | 待实测   |
| `fpr` / `benign_fpr` | 良性用例被误拦截比例                        | 待实测   |
| `task_success_rate`  | 正常任务完成率                              | 待实测   |
| `invalid_run_rate`   | 无效运行比例                                | 待实测   |
| `metrics_reliable`   | 指标是否可解释为可信结果                    | 待实测   |

建议在最终测试报告中同时给出防御前和防御后的同源样本对比，并列出 `metrics_reliability_reasons`。当使用 fake core、allow-all core 或无效运行比例过高时，不应把指标写成真实防御效果。

## 3.5 分项攻击分析

### 3.5.1 提示注入

攻击方式：攻击载荷来自不可信上下文、RAG 片段或工具返回结果，诱导模型忽略原始任务或执行攻击者指定动作。

现有检测路径：

- `PromptInjectionDetector` 对未净化、不可信、instruction-like 内容进入上下文或模型输入时输出 `ask`。
- `JailbreakDetector` 对模型输入中的越狱标记或模型输出中的敏感泄露迹象输出 `deny`。
- `EnvironmentPoisoningDetector` 对会进入上下文或持久化的工具结果污染输出 `ask`。

待补充实测：防御前后 ASR、`asr_valid`、典型事件链、误报样例。

### 3.5.2 工具劫持

攻击方式：通过工具描述污染、工具类型伪冒或 MCP 工具目录污染，使 Agent 调用与表面名称不一致的工具能力。

现有检测路径：

- `ToolHijackDetector` 对工具类别、类型、资源方向、操作类型和内置 profile 的不一致输出 `deny`。
- `UnprofiledToolResourceDetector` 对未画像工具触达 outbound、persistent、execute、write、delete 等高风险资源输出 `ask`。
- AttackBench 中 `mcp_call` 相关逻辑会补充 descriptor diff 和 hijacking metadata，用于构造更真实的工具劫持场景。

待补充实测：autonomous 与 differential 模式下的 ASR、误报率，以及工具 profile 未及时更新时的误拦截分析。

### 3.5.3 记忆污染

攻击方式：将恶意指令或错误偏好写入长期记忆或 RAG 语料，使后续会话在攻击者不再出现时仍受影响。

现有检测路径：

- `MemoryPoisoningDetector` 对不可信来源、显式 requires approval 或命中 memory poisoning marker 的持久化写入输出 `ask`。
- `EnvironmentPoisoningDetector` 对工具结果中将进入上下文或持久化的 instruction-like 内容输出 `ask`。
- AttackBench 包含 delayed、realistic、stateful、toolchain 和 PoisonedRAG 扩展样本。

待补充实测：stateful 记忆污染场景的攻击成功率、拦截率、恢复/清理效果。

### 3.5.4 文件外泄

攻击方式：诱导 Agent 读取本地敏感文件，再通过邮件、消息、API、表单提交等渠道外发。

现有检测路径：

- `SensitiveResourceDetector` 对派生资源目标中的敏感路径或敏感标记输出 `deny`。
- `OutboundDetector` 对非允许域名邮件、外发消息和 collection endpoint API 调用输出 `ask` 或 `deny`。
- 文件外泄评测中可结合 high confidence evidence，降低误判对结论的影响。

待补充实测：敏感文件读取拦截率、外发通道阻断率、浏览器表单提交场景证据。

### 3.5.5 Agent 滥用

攻击方式：请求本身可能来自用户，但目标动作违反业务策略或与当前任务不一致，例如未经确认的高风险操作、批量删除、越权调用或不必要的数据外发。

现有检测路径：

- `TaskMismatchDetector` 在不可信来源场景中检查高风险工具动作是否与用户任务文本匹配。
- `OutboundDetector`、`CodeExecDetector`、`SensitiveResourceDetector` 对外发、命令执行和敏感资源访问进行补充拦截。
- `ask` 决策可把中等风险操作移交人工审批。

待补充实测：业务副作用验证率、closure/deterministic replay 模式结果、误拦截对正常任务的影响。

## 3.7 局限性分析

当前实现的主要局限包括：

- 确定性规则便于解释，但对高度混淆、语义改写和跨轮隐蔽攻击的覆盖有限。
- `TaskMismatchDetector` 依赖工具别名和文本规则，对复杂业务语义缺少深层理解。
- `ask` 决策依赖人工处理，高并发或无人值守场景下可能增加延迟。
- 数据集虽然覆盖多类攻击，但中文、多行业和真实企业流程的泛化仍需扩充。
- OpenClaw 插件当前不做参数改写、消息改写或原生审批 UI 接管。

这些局限不影响当前系统作为运行时行为安全网关的原型价值，但在正式部署前需要结合业务权限、沙箱、密钥管理和更大规模评测共同验证。
