# 作品概述

## 1.1 背景与问题

工具增强型 LLM Agent 能够调用文件、网络、消息、代码执行、长期记忆和业务系统接口。能力扩展带来了新的安全边界：攻击并不一定需要修改模型权重，也不一定表现为最终回答中的违规文本，而可能通过运行时链路诱导 Agent 执行真实副作用，例如读取敏感文件、向外部地址发送数据、写入恶意长期记忆、调用被污染的工具，或完成未经用户明确授权的高风险业务操作。

在这种场景下，仅依赖模型安全对齐、用户输入过滤或事后日志审计存在不足：

- 模型安全对齐主要作用于训练和生成行为，无法直接约束具体工具调用是否应当执行。
- 输入过滤难以感知工具返回结果、RAG 上下文、长期记忆和运行时配置中携带的间接注入。
- 事后审计能够帮助复盘，但无法在工具执行前阻断高风险行为。

AgentGuard 的目标不是提出新的深度学习模型，也不是替代业务权限系统，而是在 Agent 运行时增加一层可解释、可审计、可阻断的行为安全控制。

## 1.2 作品定位

AgentGuard 是面向工具增强型 LLM Agent 的运行时行为监督与攻击检测系统。其核心思路是：将 Agent 的关键运行时行为抽象为标准 `GuardEvent`，在工具执行、消息发送、记忆写入、上下文组装等节点进行策略评估，并将判定结果映射为 `allow`、`deny`、`ask` 三类动作。

系统当前重点覆盖以下问题：

- 工具调用前是否访问敏感资源或偏离用户任务。
- 工具身份、工具类型、资源方向和操作类型是否符合已注册画像。
- 不可信上下文或工具结果是否携带提示注入、越狱或持久化污染风险。
- 数据是否通过邮件、消息或 API 外发到非信任目标。
- 中等风险事件是否需要人工审批，而不是简单放行或拒绝。
- 每次判定是否能够留下审计记录、规则命中证据和调用链上下文。

| -------------------- | ------------------------------------------------------------------------------------------------------------------------------------ |

## 1.4 总体架构

AgentGuard 采用四层架构，各层通过明确接口解耦：

```text
Agent Runtime
    │
    ▼
Runtime Adapter
LangGraph / OpenClaw / HTTP / subprocess
    │  GuardEvent / GuardDecision
    ▼
Guard API / Control Plane
鉴权 / 策略 / 审批 / 审计 / 指标 / Trace
    │  evaluate(event, policy)
    ▼
agentguard-core
事件契约 / 资源派生 / 检测器 / 决策合并
    │
    ▼
Dashboard / Evaluation
审批处理 / 证据链展示 / AttackBench 评测
```

各层职责如下：

- Runtime Adapter：嵌入 Agent 运行时，负责事件映射、执行前拦截和决策执行。
- Guard API / Control Plane：提供统一 HTTP 入口，负责鉴权、策略快照、审批状态、审计入库、指标查询、adapter heartbeat 和调用链查询。
- agentguard-core：无状态判定库，不读写数据库、不创建审批记录、不直接调用外部服务。
- Dashboard / Evaluation：展示风险事件、审批队列、证据链、评测结果和系统状态。

## 1.5 当前实现边界

本作品当前实现基于确定性规则、事件契约和策略配置，不依赖外部 LLM 或 embedding 模型完成安全判定。因此，它具备较好的可解释性和低依赖性，但也存在规则覆盖有限的问题。

需要明确的边界包括：

- 不防御模型权重投毒、训练数据污染或模型供应链攻击。
- 不替代应用系统自身的身份认证、权限管理和数据访问控制。
- 不承诺覆盖所有提示注入或所有 Agent 攻击。
- 不把未运行的评测指标写成已完成结果。
- OpenClaw 接入当前是 hook-only 插件形态，已实现多个 hook 的事件映射和阻断/观察逻辑，但不接管 OpenClaw 原生审批 UI，也不实现消息或工具参数改写。

## 1.6 交付形态

面向正式参赛材料，AgentGuard 的交付重点是完整说明“为什么需要运行时行为监督、系统如何实现、实现覆盖哪些攻击面、如何评测、创新点在哪里以及当前边界是什么”。本报告后续章节分别给出设计实现、测试分析、创新性说明、总结与参考文献。
