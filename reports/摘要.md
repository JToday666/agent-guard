# 摘要

随着大模型 Agent 从对话问答扩展到文件读写、网络请求、代码执行、长期记忆和外部工具调用，其主要安全风险不再只表现为模型输出中的不当文本，而是进一步转化为运行时的外部行为风险。攻击者可以通过间接提示注入、工具描述污染、敏感文件读取、数据外发、长期记忆污染或业务流程滥用，诱导 Agent 在合法工具权限内执行偏离用户真实任务的动作。传统输入过滤、越狱检测和事后日志分析难以覆盖这类工具调用链路中的执行前拦截、审批和证据追踪需求。

AgentGuard 面向工具增强型 LLM Agent，设计并实现了一套运行时行为监督与攻击检测系统。系统采用 Runtime Adapter、Guard API / Control Plane、agentguard-core、Dashboard / Evaluation 四层架构：Adapter 在 Agent 工具执行前后采集标准化安全事件；Guard API 负责鉴权、策略快照、审批、审计、指标和调用链状态；agentguard-core 作为无状态判定内核，基于事件契约、资源派生、工具画像和策略规则输出 `allow`、`deny`、`ask` 三态决策；Dashboard 与 AttackBench 分别承担运营展示和攻击评测任务。

现有实现中，Core 默认组合 10 类检测器，覆盖敏感资源访问、工具身份不匹配、未画像工具高风险资源访问、数据外发、任务不一致、提示注入、越狱/模型泄露、危险代码执行、长期记忆污染和工具结果污染等风险。事件模型定义 7 类 `GuardEventType`，并为不同 payload 类型建立结构化校验。LangGraph 侧通过 `SecureToolNode` 与 `GuardedToolGateway` 在工具调用前同步评估，OpenClaw 侧通过 hook-only 插件接入工具调用、消息发送、安装配置审计、工具结果持久化和运行时观察事件。Guard API 进一步提供审批 nonce、CSRF 校验、审计 hash chain 和 provenance graph，为阻断结果提供可解释证据链。

AttackBench 提供面向行为副作用的评测框架，当前主 AttackCase 数据集 123 条，PoisonedRAG 扩展 12 条，合计 135 条，覆盖提示注入、工具劫持、记忆污染、文件外泄、Agent 滥用和良性对照场景。评测引入 `metrics_reliable` 可信度标记，区分统计可信与仅供参考的结论；部分场景支持真实浏览器自动化评测，比仅依赖文本判断更贴近真实攻击链路。由于本报告整理阶段未重新运行评测，ASR、Block Rate、FPR、延迟等量化结果均保留为待实测项，以最终测试报告为准。

关键词：LLM Agent 安全；运行时行为监督；工具调用防护；提示注入；审计溯源；攻击评测
